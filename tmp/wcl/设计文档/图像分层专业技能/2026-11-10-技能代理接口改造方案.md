# 图像分层专业技能：技能代理接口改造方案

> 状态：客户端代理工具和技能包已按本文实现，本地定向测试及最新产物构建通过；用户已确认当前测试环境中的图像分层调用符合预期。核对时间：2026-11-10；服务参考仓库 `insight-harness-service` 的读取版本为 `5efedc7`。本文取代旧方案中通过 `/api/generation/submit` 和 `GET /api/generation/{id}` 创建、查询图像分层任务的规定；旧文档保留为历史记录。

## 1. 目标、已有证据与决策

用户在当前会话上传一张图片，可给处理提示词和分层数量。技能先用现有 `upload_attachment` 得到 OSS URL，再用 `POST /api/skill-proxy/call-insight-api` 创建及查询异步图像分层任务。用户未给层数时传整数 `0`，未给提示词时传空字符串。只有拿到真实 PSD、下载进当前会话工作区并通过聊天文件卡片交付，才算完成本次 PSD 目标。

| 证据 | 对设计的约束 |
| --- | --- |
| 只读服务仓库 `docs/设计规范/implementation/call-insight-api-proxy-contract.md`、`api-manager-image-layering-input-contract.md` | 外层固定 `POST /api/skill-proxy/call-insight-api`，请求 JSON 为 `{method,path,body}`；创建 `path=/v1/proxy_async_create`，查询 `path=/v1/proxy_async_get_result`；返回 NDJSON，不是旧生成接口的 JSON 任务记录。 |
| `src/insight_harness_service/insight_skill_tasks.py` | 创建响应的 `data.task_id_list` 已替换成绑定用户、连接及查询类型的句柄，有效期 24 小时；查询不能提交原始上游 ID。该代理不创建 `generation_tasks` 行。 |
| `docs/设计规范/verification/tencent-multi-layer-fourth-run-2026-11-10.md` | 四轮真实上游任务均成功；前三轮只有 PNG，第四轮有 10 个 PNG 和 1 个 PSD，PSD 在 `data.image_list` 末项。第四轮对 PSD 的 HEAD 返回 `image/vnd.adobe.photoshop`、13,552,090 字节；这未证明每次都会生成 PSD，也未证明 PSD 内部确有可编辑图层。该轮经本地 FastAPI TestClient 与真实上游完成，不证明客户端目标 Gateway 已部署同一服务版本。 |
| 当前客户端 `packages/insight/media-upload/src/image-layering.ts` | `submit_image_layering`、`get_image_layering` 已调用新代理入口并解析 NDJSON、`taskHandle`、Jobs 结果及 PSD URL；不调用旧生成接口。 |
| `packages/insight/desktop-integration/src/host/skill-proxy-request.ts` | Host 鉴权请求函数限制为固定 `/api/skill-proxy/<连接名>` POST，已由 `host.ts` 导出供媒体上传插件调用。 |
| `packages/deliverables/tool-present/README.zh.md`、`packages/client/ui-deliverables` 与 `packages/bundle/web-app/presets/standard.patch.yml` | 默认 `standard` preset 挂载 Shell 和 `present`；`present` 可将当前 Session 可访问的普通文件登记为聊天交付卡片，记录路径而不复制内容。PSD 的卡片和本地打开可作为交付，不承诺在聊天内直接渲染 PSD 图层。 |

**实施选择：**沿用当前 Host 工具和 Jobs 处理生成，改用已有 Host 技能代理鉴权请求函数；仅为最终 PSD 文件增加受限下载步骤，技能在同一 Session 调用 `present`。这样长时间生成仍由会话 Job 跟踪，模型只需保存代理句柄，不在 Shell 里读取账号 Token，也不直接访问 API Manager。`insight-harness-service` 只读，不在本项目改动范围内。

## 2. 调用链和三类标识

```text
本轮用户图片 -> upload_attachment -> 上传中心 STS -> OSS PUT -> 来源图片 URL
  -> submit_image_layering -> POST /insight-harness-service/api/skill-proxy/call-insight-api
       path=/v1/proxy_async_create -> NDJSON result -> taskHandle
  -> 会话 Job -> 定时 POST 同一服务接口
       path=/v1/proxy_async_get_result，携带 taskHandle
  -> NDJSON result，业务 status=success -> data.image_list 中定位 PSD URL
  -> 受限下载到当前 Session 工作区 -> present({files:[{path: 本地 PSD}]})
  -> 聊天文件卡片 + 本地文件链接 + 状态说明
```

| 标识 | 来源 | 用途 |
| --- | --- | --- |
| `taskHandle` | 创建终结事件 `body.data.task_id_list[0]` | 当前账号查询上游任务；不是 UUID，也不是旧 `generationId`。必须进入当前 Session 可恢复的工具结果，查询时原样传回。 |
| `jobId` | 客户端 `ctx.jobs.start` | 仅标识本地跟踪任务；客户端重启后不可单靠它恢复上游查询。 |
| `proxyRequestId` | 每次代理调用的 `X-Insight-Proxy-Request-Id` 响应头 | 审计及结果不明时的定位线索；创建和每次查询各不相同，不可当作 `taskHandle`。 |

当前 `get_image_layering({taskHandle})` 已采用新句柄；技能正文、工具 schema、README、模型可见快照和消费者已按该字段更新。旧 `generationId` 不能被当作新句柄使用。`watch: true` 只恢复本地轮询，不再次创建。

## 3. 代理请求与结果判定

客户端只调用固定测试环境基址 `https://gapi-test.insight-aigc.com/insight-harness-service`（生产由已有环境配置选择），发送以下创建包；Host 鉴权请求函数提供当前账号 Token，不将 Token、AK/SK 或 `biz_info` 放入技能参数和模型输出。

```json
{
  "method": "POST",
  "path": "/v1/proxy_async_create",
  "body": {
    "model_id": "decompose-1.0-flash",
    "task_type": "async_tencent_multi_layer_create",
    "data": {
      "prompt": "",
      "image_url_list": ["https://example.invalid/from-current-upload.png"],
      "image_params": {"num_layers": 0}
    }
  }
}
```

上例 URL 是占位符，不可用于实测。提交工具只接受当前会话本轮成功 `upload_attachment` 的单张图片 URL，核对记录来源、HTTPS 及受信 OSS 域名；`num_layers` 要求非负安全整数并原样传递。代理服务只校验 `data` 是对象，不代客户端检验图片数量、图片来源、提示词类型或层数。四次真实创建验证了 `num_layers=0`，**尚无空提示词上游实测**；空字符串仍按用户既定要求传入，若上游拒绝则明确报告，不偷偷补造提示词。

前置校验失败可能是普通 HTTP 4xx/5xx。进入代理后，外层 HTTP 200 和 `accepted`/`heartbeat` 都不代表创建成功；按流读取至唯一终结事件，限制总字节数及单行长度，并解析：`type=result`、上游 `status` 为 2xx、`body.code=0`、`body.data.task_id_list` 为非空字符串数组，才记录服务签发的 `taskHandle`。保留 `proxyRequestId` 供诊断；不在一般日志中输出句柄、原图 URL 的签名参数或原始响应体。

使用同一代理入口查询，`body` 恰好只有两个字段：

```json
{
  "method": "POST",
  "path": "/v1/proxy_async_get_result",
  "body": {
    "task_type": "async_tencent_multi_layer_get_result",
    "task_id": "<创建响应中的 taskHandle>"
  }
}
```

查询终结 `result` 的上游 HTTP 为 2xx 且 `body.code=0` 后，按业务 `body.status` 判读：`running` 继续有界轮询；`success` 再检查 `body.data.image_list`；明确失败状态终止并报告；未知状态保留句柄并报告未确认。不得把代理 HTTP 200 或 Job 完成单独视为 PSD 生成成功。服务端可在查询返回时将 `body.task_id` 改回客户端句柄；客户端始终以最初的 `taskHandle` 为准。

## 4. 长耗时、取消与恢复

`submit_image_layering` 只发一次创建 POST，等终结事件拿到 `taskHandle` 后立即将句柄作为工具结果写入 Session，再启动当前会话的 Job；Job 只做查询 POST，不重复创建。代理单次请求可能发送心跳并等待最多约 1,200 秒；当前工具默认 15 秒、上限 120 秒的请求超时不能原样用于新协议。实现时须让可配置的单次代理操作上限与服务和客户端约 1,250 秒的限制协调，同时分别限定生成任务的总跟踪时间与查询间隔，避免模型长时间同步轮询。若实际创建阶段经常长时间等待句柄，需要再评估把创建移入 Job 并持久记录句柄的方案，不把 `accepted` 当作已拿到句柄。

若创建 POST 已发出但流超时、断连或终结事件缺少有效句柄，结果是 `submission_unknown`：保留已收到的 `proxyRequestId`，提示核对代理审计，不自动重发付费创建。句柄已取得但 Job 注册失败时仍返回句柄和 `monitoring_unavailable`。查询失败、Job 被终止或本地跟踪超时时保留句柄，不能写成远端失败；在 24 小时有效期内可由 `get_image_layering({taskHandle,watch:true})` 查询并恢复跟踪。超过有效期或服务拒绝该句柄时直接报告不可恢复，不改用上游原始任务 ID。

## 5. PSD 识别、工作区下载和聊天交付

四次真实成功结果均以 `body.data.image_list` 返回图片，第四次的 PSD 与 PNG 共处此列表；本地服务模拟测试另有单独的 `data.psd_url`，客户端也接受该可选字段。不能依赖旧接口的 `products[].url`。逐项解析 HTTPS URL 的 pathname，大小写无关地识别 `.psd` 扩展名，允许合法查询参数但不把它写入普通日志。若有多个 PSD，逐个下载并按 `present` 的单次文件数上限分批交付；若没有 PSD，明确报告“上游已完成但未返回 PSD”，可说明 PNG 结果数量及保留句柄，**不把 PNG 当作 PSD，也不自动再次付费创建**。

技能包中的 `scripts/download_psd.mjs` 只接受 PSD URL，使用当前会话的 Shell 工具执行，并写入当前工作目录；不从本地代理描述文件或客户端存储读取 Token。脚本默认只允许已验证的测试结果 OSS 主机；生产主机须通过 `INSIGHT_LAYERING_PSD_HOSTS` 配置。它拒绝重定向、URL 用户凭据和非 HTTPS 地址；流式下载限制为 256 MiB、120 秒，核对 PSD 内容类型及 `8BPS` 文件头，将字节写到工作区 `generated/image-layering/` 下的临时文件，完整成功后原子改名为唯一的 `.psd` 文件。文件名不包含句柄或不可信 URL 片段。下载失败时保留已取得的远端 PSD URL 与句柄，报告本地交付失败，不重新创建生成任务。目标 Desktop 的工作区写权限和正式环境主机仍需联调。

下载后的文件必须由当前 Session 的 `present({files:[{path,description:"图像分层 PSD"}]})` 登记交付，最终回复给出本地文件链接和必要的远端 URL。`present` 要求当前 Agent 有开放轮次、文件在 Session 文件系统中可访问；它不复制文件内容，Web 在轮次结束后显示文件卡片。PSD 在聊天中作为**可打开的文件产物**呈现，不承诺内嵌 PSD 图层预览；若需视觉预览，可另选一张结果 PNG 展示，但不能替代 PSD 卡片。若 Job 完成时没有开放轮次，先由完成通知唤起下一轮，再执行下载与 `present`。
