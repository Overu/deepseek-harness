# 图像分层：版权限制失败提示映射方案

状态：方案已落实，单图版权失败提示已在 Insight 测试环境客户端由用户验证。功能代码只修改 `packages/insight/media-upload/` 内的图像分层插件、技能与测试；同步更新该包 README 和 `docs/insight/` 对应的英中文档。没有修改会话内核、导出器或只读的 `insight-harness-service`。

## 目标与现状

用户提供的测试环境代理审计显示，查询 `/v1/proxy_async_get_result` 的 NDJSON 终结事件为 `type=result`、上游 HTTP `status=200`，`body={code:3099,message:"输出图像可能涉及版权限制，任务无法完成",status:"failed",data:{}}`，代理请求 ID 在响应头。这里的“可能”是上游对版权相关限制的判断，不等于输入图片已被认定侵权；`data` 没有 PSD 或分层图像。

当前 `packages/insight/media-upload/src/image-layering.ts` 在 `requestProxy` 读取整个终结事件后，因 `body.code !== 0` 立即抛出 `STATUS_UNAVAILABLE`，只保留业务码和代理请求 ID。`body.status` 与 `body.message` 未进入 `parseLayeringResult`。`readStatus` 将其变为 `query_unavailable / business_error / remoteOutcome: unknown`，Job 停止该图跟踪，技能只能给出泛化的“结果未知”说明。仅改技能文本无法取得被 Host 丢弃的字段。

## 已落实的处理规则

对**上游 HTTP 2xx 的结果查询**增加一条窄分支：`body.status === "failed"` 且 `body.code` 为非零业务码时，把它作为服务端明确失败处理，使用现有 `LayeringResult.status = "failed"` 与 `error` 字段。`body.code === 0` 且 `status=failed` 的现有路径也共用同一用户提示映射。创建请求、HTTP 非 2xx、`type=error`、缺失或非 `failed` 的状态沿用现有行为。尤其不能仅凭 `3099` 断定版权限制；没有明确终态的 `3099` 仍是 `query_unavailable / remoteOutcome: unknown`。

Host 读取 `body.message`，只将**已确认的版权限制消息**映射为固定的用户提示，不把上游原文直接交给模型或用户。第一版仅识别本次审计中的完整消息（允许首尾空白）；其他文本，包括长度异常、非字符串、包含附加指令或新措辞的消息，都走通用失败提示。此处是当前上游缺少稳定错误类别时的有限适配；以后如服务端提供结构化版权原因，应改用该字段，不能扩展为对任意文案的模糊关键词推断。保留 `businessCode`、`proxyRequestId` 供内部排查，普通回复不展示。原始 `body.message` 仅进入下述受限 Host 诊断日志。

| 已验证的输入条件 | Host 工具结果 | 技能面向用户的简短回复 |
| --- | --- | --- |
| `status=failed`，`message` 为“输出图像可能涉及版权限制，任务无法完成” | `status=failed`；`error` 为固定版权提示；无文件地址 | “因版权相关限制，这张图片的分层处理失败。请更换一张图片再试。” |
| `status=failed`，但消息未命中上述已确认文本 | `status=failed`；`error` 为通用失败提示 | “这张图片的分层处理未能完成，请稍后再试。”不声称版权原因。 |
| `code=3099`，缺少明确 `status=failed`，或响应结构不可信 | 保持 `query_unavailable / business_error / remoteOutcome: unknown` | “暂时无法确认这张图片的处理结果，请先核对原任务，避免重复提交。”不声称版权原因或远端失败。 |
| 登录、上传、创建、查询超时、结果缓存或下载错误 | 保持各自现有状态与恢复规则 | 按实际失败阶段说明；不套用版权文案。 |

技能在确认版权失败时逐图转述固定安全提示，不扩写恢复路径；不得说用户侵权、图片本身违法，或把“可能涉及版权限制”升级成法律结论。最终回复不出现 `3099`、接口路径、任务句柄、代理请求 ID 或空 `data`。多图任务只给受影响图片贴该提示，其他图片继续处理，最后逐图汇总。实际客户端中曾出现未经证实的“提供授权来源信息”建议，后续收敛及验证记录见[版权失败回复优化记录](./2026-11-18-版权失败回复不建议授权材料.md)。

## 插件内诊断日志与导出限制

每次**生成结果处理阶段的查询终结事件表达失败或业务异常**时，图像分层插件用现有 `ctx.logger.warn` 写一条结构化 Host 运行日志，覆盖后台 Job、人工 `get_image_layering` 查询和结果缓存前的同句柄查询；文件卡片点击后的再次校验属于独立下载流程，本方案不扩展其诊断行为。记录阶段、固定接口路径、会话或调用关联标识（取得时）、同句柄查询尝试次数、响应头代理请求 ID、代理外层 HTTP 状态、终结事件 `type` 与上游 `status`、`body.code`、`body.status`、`body.message`、`body.data` 摘要及 Host 最终分类。只记实际取得的字段；若流未完整返回，记录超时或解析失败及可确定的信息，不能虚构上游状态。

本次已知响应的 Host 日志保留原文 `body.message="输出图像可能涉及版权限制，任务无法完成"`、`body.code=3099`、`body.status="failed"`、`body.data={}`、终结事件上游 `status=200` 和响应头代理请求 ID，方便与上游代理审计核对。未来非空 `data` 只记字段名、类型和数量等摘要；未知消息设长度上限，脱敏 URL 与疑似凭据，并标记截断或脱敏。不记录原图、产物 URL、Token、Cookie 或完整请求正文。日志文本不作为模型指令或用户回复；正常 `running` 不逐次警告。写日志失败不能改变原任务结果。

**导出能力限制：**当前客户端的“下载 Session 日志”ZIP 只包含会话事件和附件，不含 `ctx.logger` 运行日志；插件目录内也没有能够写入“仅在 ZIP 中可见、且不会进入模型或聊天”的正式会话事件 API。Core Session 的 `appendPluginRecord()` 仅允许实验包调用，不能从本插件绕用。因此当前实现只能保证 Host 运行日志有上述细节，并让现有工具/Job 结果保留安全的 `businessCode`、`proxyRequestId` 供会话 ZIP 与 Host/上游日志关联；**不能保证只凭会话 ZIP 还原原始 `body.message`**。目标测试客户端如何持久化或收集 Host 运行日志仍需实机确认；若没有可用的导出方式，应明确告知用户该限制，而不是声称“导出会话日志即可看到完整报文”。

## 实现范围与调用关系

1. `packages/insight/media-upload/src/image-layering.ts`：在查询的非零业务码路径识别服务端明确 `failed`，并在现有 `error` 字段输出经 Host 固定映射的简短提示。保留其他业务错误的未知状态、现有单次停止规则及超时同句柄补查规则。`parseLayeringResult` 的现有 `failed` 分支共用这份映射；无需添加新工具、修改全局错误处理或新增对外字段。在丢弃响应字段前写结构化 Host 诊断日志；原始上游 `message` 不进入工具结果、Job 结果或普通聊天。
2. `packages/insight/media-upload/guidance/image-layering/SKILL.md`：明确 `failed` 时优先使用工具提供的安全 `error` 文案，版权提示要求换图；`query_unavailable` 仍表示未确认，不得依据 `businessCode` 推测版权或自动重建任务。保留多图独立处理、一条最终汇总及不自动重复付费创建的规则。
3. 同步更新该包 README 英中版本及已存在的 `docs/insight/image-layering` 英中说明，修正已过时的“所有非零业务码均未知”表述，准确说明 Host 日志与会话 ZIP 的区别。仅更新与本行为有关的段落、配对记录和必要的模型可见快照。不修改只读的 `insight-harness-service` 仓库，也不改变上传附件工具或通用权限策略；如果 `docs/insight/` 也不在获准修改目录内，则仅更新插件包内 README 与本方案，并报告文档同步限制。

## 自测与验收标准

- 用本次完整 NDJSON 事件作为聚焦用例：查询工具及后台 Job 都返回 `failed`、固定版权提示与原任务句柄；只查询一次，不重新提交、不缓存或展示文件；模型最终只给通俗版权限制原因及换图建议。
- 反例：同为 `3099`，但无 `status=failed` 或消息不是已确认版权文本时，不输出版权原因；无明确终态者仍保留 `remoteOutcome: unknown`。包含指令、URL、控制字符或超长内容的 `message` 不原样进入模型输出或普通日志。
- 日志验收：模拟本次完整终结事件，拦截插件 `ctx.logger.warn` 并核对消息原文、业务码、远端状态、空 `data`、两个 HTTP 状态、代理请求 ID、尝试次数与 Host 分类；后台 Job、直接查询、超时及缺失请求 ID 都验证。模拟 URL、凭据、超长消息和非空 `data`，确认敏感内容不写入日志；模型可见工具/Job 结果不含上游原文。验证测试客户端能否单独收集 Host 日志，不以会话 ZIP 测试替代。
- 回归：`code=0` 的 `running/success/failed`、非版权失败、认证失败、查询超时同句柄最多一次补查、创建结果未知、多图一图失败其余继续、文件清单与下载行为不变。现有 `image-layering.spec.ts` 增加聚焦断言；涉及模型可见输出时更新并运行对应无密钥会话快照。
- 构建与文档：聚焦 Vitest、双语配对、Markdown 检查、`build:artifacts` 后 `build:check` 通过；按仓库要求核对提交差异。真实服务联调仅在用户确认方案并完成实现后验证，不因测试自动新建额外付费任务。

## 落地与自检结果

`requestProxy` 在已认证代理的 NDJSON 查询终结事件中读取 `body.code`、`body.status` 和 `body.message`。只有上游 HTTP 2xx、整数业务码、明确 `status=failed` 时才进入已确认失败；原始消息仅用于匹配已知版权限制文本和受限 Host 诊断日志。工具和 Job 使用现有 `status=failed`、安全 `error`、业务码与代理请求 ID；没有新增会话事件或对外字段。只有业务码、没有明确失败状态的响应继续返回 `query_unavailable / remoteOutcome: unknown`。后台 Job 对单图失败终止本地图像任务，其他图片仍继续；不自动重建付费任务。

本地模拟上游响应验证：版权限制样例返回固定换图提示，消息原文没有进入模型可见工具结果；其他消息返回通用提示，日志中的 URL 与疑似凭据被脱敏、非空 `data` 只记摘要；Host logger 抛错不改变查询结果。包内 Vitest 共 5 个文件、44 个用例通过；包级 TypeScript 构建、`build:artifacts` 8/8、其后的 Host/Client `build:check` 2/2、修改过的 TypeScript 文件的 oxlint、双语配对、Markdown 换行与链接检查、`git diff --check` 均通过。用户随后在测试环境客户端提交单图并提供截图：后台 Job 显示失败，最终回复为“因版权相关限制，这张图片的分层处理失败。请更换一张图片再试。”，未出现额外恢复建议。这是版权失败提示的单次实测，不验证成功生成或下载 PSD。

最初在沙箱中启动 `tsx` 出现 `uv_os_get_passwd` 的 `ENOMEM`，`pnpm` 也被 NVM 防火墙阻断；改为宿主环境运行相同仓库构建命令后，`build:artifacts` 与 `build:check` 均通过。仓库级 `doc-sync` 43 项中 40 项通过、3 项失败，分别来自本次未修改的 `univer-office` JSDoc、其他包与补丁中的禁用词，以及 Windows 临时目录符号链接 EPERM；本次修改涉及的双语配对、Markdown 换行与链接检查均通过。Host 运行日志能否在目标测试客户端持久收集仍未实机验证；下载的 Session ZIP 本身不含 Host logger 输出，不能只凭会话 ZIP 声称拿到了原始上游消息。
