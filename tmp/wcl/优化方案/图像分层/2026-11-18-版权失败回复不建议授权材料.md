# 图像分层版权失败回复：停止建议授权材料

## 现场与证据边界

2026-11-18 的因赛AI 测试截图显示，用户提交单图分层后，最终回复已说明版权相关限制导致任务未完成、没有 PSD 或分层图像，却额外写出“如果分层需求较急，也可以先提供图片的授权来源信息”。截图未展示服务端支持此操作的接口、受理规则或成功案例。当时的 Host 结果映射只提供“这张图片的分层处理触发了版权相关限制，未能完成。请换一张图片再试。”；当时的技能指令虽要求换图，却允许“简短润色”，没有明确禁止增添未经验证的恢复方式。可以确认最终回复超出了已验证的处理范围；不能仅凭截图断定下游是否接受授权材料，也不以猜测设计新的请求参数或重试链路。

## 本次优化

- 收紧 `packages/insight/media-upload/guidance/image-layering/SKILL.md`：工具明确返回 `failed` 且安全 `error` 指向版权相关限制时，单图直接回复该 `error` 原句；多图仅添加图片标签并汇总其他图片。不得追加解释、授权材料建议、改模型或改提示词等未经验证的恢复方式，也不主动追问用户是否拥有授权。用户后来明确选用另一张仍在最近三个用户轮次范围内的图片，或上传新图并要求处理时，才进入既有选图与提交流程；失败的原图不自动重试。
- 保持 Host `body.message` 的精确匹配、`failed` 分类、诊断日志和已付费任务的停止规则不变。当前有证据支持的下一步只有请用户换图；本次不调用新接口、不重新提交同图，也不把版权限制等同于用户侵权。
- 同步更新插件 README 英中文档。此记录只说明已验证的交互边界，不宣称上游永久不支持授权材料；若将来获得正式接口文档及联调结果，再单独设计该能力。

## 验收

静态检查：确认打包的技能指令含版权失败的限定回复，插件 README 配对一致，Markdown 检查通过；包内测试保持通过。客户端验收：使用能稳定返回已确认版权失败的测试任务，在新会话中核对最终回复只说明本次未完成并请用户换图，不出现“提供授权来源/证明”、模型厂商受理推测或同图重试建议。客户端实测可能产生付费任务，须由测试人员按已有测试环境流程执行；当前文档和代码自检不替代这项实测。

## 第二次文案收敛

用户进一步要求单图版权失败只给一句话。现把 Host 的固定 `error` 改为“因版权相关限制，这张图片的分层处理失败。请更换一张图片再试。”；技能在单图场景只输出该原句，多图场景只加必要的图片标签。技能指令不再列举不应提出的具体替代方案，以免这些词汇再次进入模型回复。Host 对失败状态的判定、接口调用、日志和已付费任务规则不变；这句文案也不表示对图片侵权的法律认定。

第二次收敛后，媒体上传包内 Vitest 5 个文件、44 个用例通过；包级 TypeScript 构建、改动文件的 oxlint、`build:artifacts` 8/8、其后的 `build:check` 2/2、双语配对、Markdown 换行与链接检查、`git diff --check` 通过。仓库级 `doc-sync` 共 43 项，40 项通过、3 项失败：`univer-office` 中原有导出函数缺少 JSDoc、其他包及补丁含 `provenance` 禁用词、Windows 临时目录创建符号链接返回 EPERM；这些失败没有指向本次图像分层文案。
