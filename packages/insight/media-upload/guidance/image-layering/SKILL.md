# 图像分层

`image-layering` 是技能名，不是可调用的工具名。仅询问技能作用时，用一两句说明“选择图片，交给图像分层模型处理，然后交付 PSD 和分层图像”；必要时说明图片会上传用于处理。仅问功能或模型名称时，不调用来源、上传或生成工具；对外只称“图像分层模型”。

## 选择图片与层数

1. 调用 `prepare_image_layering_source` 查看本 Session 最近三个含用户直接消息的轮次中的图片。若没有可用图片，请用户重新上传；仅一张时选它。多张时，用户已明确指出图片或“全部”就按该选择处理；本轮仅上传一张且用户说“这张图”时选本轮图。其余情况用 `ask_user_question` 的 `multi_select: true` 多选，选项标签用“图 1 · 文件名 · 本轮”等短且唯一的文字，并记住标签到 `sourceRef` 的对应关系。只按列出的标签确定来源；同名图用序号和轮次区别，不能凭文件名猜测；不得读取其他 Session、文本路径或模型猜测的 URL。
2. 在任何上传或创建任务前，检查选中的不同 `sourceRef` 数量。超过五张时说明“单次最多处理 5 张，请重新选择”，再让用户多选；不得自动截取前五张。选图答案的 `custom` 可能补充已勾选项：若它可能改变图片集合，先澄清完整选择并重新计数。跳过、取消或没有选中图片时不提交；定时模式返回 `pending` 时保留原问题等待答案，也不提交。相同已存储内容在来源列表中只出现一次。
3. 对每张选中图片确定层数策略：用户明确指定 `2–17` 内的整数就采用该数；明确选择智能分层，或明确说用 `0` 表示自动时才传 `0`；明确指定下述四个预设区间之一时按该区间选数。`0 层`、`1`、大于 `17`、负数、小数等无效值须先提醒“当前只支持智能分层或指定 2–17 层”，请用户修正，不得截断、改成自动或先上传该图。用户明确说所有图片共用一项策略时才应用到全部；逐图说明必须能唯一对应图片。
4. 只对尚未确定策略的图片调用 `ask_user_question`：单图问一次，多图在一次调用中为每张分别提一个单选问题，以“图 1/3 · 文件名”等短标题分页展示。每题只给“智能分层”“基础 · 2–4 层”“常规 · 5–8 层”“精细 · 9–12 层”“高精细 · 13–17 层”五个选项，区间两端均包含在内；简短说明层数越多费用可能越高，自动模式无法据此预估费用。不要标记推荐选项。“输入你的答案”是问答卡自带入口，不另加选项。按问题 ID 对应图片，不按答案顺序猜测。单选题的 `custom` 会替代所选项；仅接受明确的自动模式、`2–17` 内整数或上述区间，其他内容先澄清。空 `selected` 且无 `custom` 才是跳过：该图片不提交，也不默认传 `0`。定时模式返回 `pending` 时保留原问题等待答案，不重复提问；用户取消整组问答时，不提交这组尚未确认层数的图片；其他问答故障才重新询问。其他参数完整的图片可继续，最后告知哪些图片未处理。
5. 用户选择区间后，针对该图可见的画面主体、前后景、遮挡和编辑目标，在所选区间内选满足编辑目标的较少整数；不得机械取中点、上界或把同一个数套给所有图片，也不得跨出所选区间。若看不到该图内容，请用户重新上传或直接指定 `2–17` 内整数，不凭文件名、大小或 `sourceRef` 猜测。自动模式无需视觉选数。用户给出的其他范围或前后矛盾的层数要求须先澄清。

## 提交与交付

1. 选图和层数确定后，对每张可处理图片分别调用 `submit_image_layering({sourceRef,prompt,numLayers})`，始终传入已选 `sourceRef` 和明确的数值。`prompt` 只保留用户对图像处理的要求，避免包含已被更正的层数或区间文案；没有要求时为 `""`。工具会再次验证 `sourceRef`；若来源已失效，请用户重新上传或选择，不用同名图片替代。工具在 Host 内上传已存储图片并创建任务：普通图片使用归一化字节，作为文件附件上传的图片保持文件字节；不得声称一定上传了原图。此流程不调用普通 `upload_attachment`，也不要求用户再次同意 OSS 上传。不要将技能名当工具名调用。
2. 按图片分别保存 `taskHandle`，前一张开始远端生成后可继续提交下一张；各自的 Job 可重叠运行。用户要求停止时，不再提交尚未提交的图片。已有 Job 时只通过 `job_output` 等待其结果，不并行查询同一句柄，也不用 Shell 或 PowerShell 睡眠命令反复探测。Job 无法启动时才用 `get_image_layering({taskHandle,watch:true})` 恢复跟踪。`job_kill` 只停止本地跟踪，不取消远端生成。`proxyRequestId` 和 `jobId` 不能替代 `taskHandle`；一张失败不取消其他图片。插件不再记录创建预留，重复调用 `submit_image_layering` 可能创建并计费另一个远端任务；不得把重新提交当作状态查询。
3. 每张图片独立记录运行、完整交付、查询错误、查询超时后状态未知或结果清单保存失败。`query_unavailable` 且 `reason` 不是 `query_timeout` 时，第一次错误即停止该图的查询和本次处理；`query_timeout` 表示工具在期限内最多对同一句柄补查一次后仍失败，也停止本次处理。不要再调用该图的 `get_image_layering` 或 `submit_image_layering`。远端明确 `failed`、`cancelled` 时不自动复查或重新创建付费任务；结果缺少 PSD 但仍有分层图片时，可保存清单并标为不完整。其他图片照常提交、跟踪和保存清单。`AUTH_REQUIRED` 或 `AUTH_UNAVAILABLE` 属于公共权限问题，应停止尚未提交的图片，并保留已提交任务的句柄。
4. 对每张已完成或缺少 PSD 但仍有图片的任务，调用一次 `cache_image_layering_result({taskHandle,imageLabel})`。`imageLabel` 使用“图片 1（原文件名）”等短且唯一的标签；工具重新查询同一句柄，将 PSD 与分层图像的 URL 清单写为当前工作区 `generated/image-layering/` 下的 JSON，并把每个结果加入会话文件卡片。它不会预先下载 PSD 或图片。只有返回 `complete: true` 才称为完整结果；保存失败只重试同一句柄的清单保存，不重新创建任务。
5. 等所有未报错图片完成、明确失败或达到本地跟踪期限后，只用一条回复汇总全部图片。结果工具的成功回执会在本轮下方按原图标题显示 PSD 和分层图片的远端文件卡片；用户点击卡片上的“下载”即直接下载，不需要再次确认。不再对 OSS URL 调用 `present`。全部完整时回复“处理完成，文件见下方”；有失败或未提交时逐图说明。非超时查询错误的图片使用“原任务处理失败；请更换图像。重新提交前请先核对原任务是否已在远端完成，以免重复生成或计费。”这表示本次处理未取得结果，不表示已确认远端生成失败或图片损坏。超时后仍无法查询时说明状态未知；清单保存错误应说明本地阶段。不要在普通完成回复中列远端 URL、绝对路径、任务句柄、内部状态或未经验证的实际图层数。

## 停止与错误

- 上传、付费创建、查询、清单保存、用户下载是不同阶段。失败时只报告实际失败阶段及可执行的下一步；HTTP 200、Job 结束或清单写入均不单独证明用户已下载文件。
- 结果诊断中的 `field`、`reason`、`valueType`、`queryAttempt` 和 `proxyRequestId` 可用于排障，不要把 `psd_url` 错误说成 `image_list` 错误；不要在普通回复中输出带签名参数的 URL。
- Host 清单保存因主机配置或沙箱失败时，保留 `taskHandle` 并报告保存失败；用户点击下载后若远端地址失效、鉴权失败或文件验证失败，由文件卡片显示失败并允许再次点击，不重新提交付费任务。不得改用 Shell、PowerShell、curl、Python 或兼容脚本下载结果，不得关闭证书校验。Windows 或 macOS 的工作区不可写时，向用户说明需要调整的目录权限并等待确认；不自行修改 ACL、owner 或执行权限修复命令。
