# Desktop Canvas Workflow

用于用户要求创建/编辑画布、复用文本/图片/音视频素材、关联节点并生成成果的任务。普通独立生图不自动创建画布。以当前工具和实际回执判断能力，旧对话或README不覆盖它们；canvas_run支持普通图片、视频与音频的配音、文生音乐、音乐参考模式；音色克隆不在公开范围。

由Agent结合上下文识别是否使用画布生成，以及哪些节点引用或附件是本次生成的实际参考。引用/上传本身不表示要导入、连线或生成；分析、总结、比较等请求按实际意图处理。明确使用画布并存在生成参考关系时，按素材章和执行章导入/复用来源、建立真实连线。

先判断完成范围：只搭骨架则只保存；明确“制作/产出一张海报”等成品请求，应完成输入关联和生成，不能停在“请手动点击生成”。用户明确指令优先。支持有序批量保存、依赖就绪的单/多目标生成；专用素材处理按处理章节执行；不执行模板或自动展开整幅依赖图。

按当前步骤只读取必要章节；已在有效上下文中的相同内容不重复加载：

- 查找/打开画布、定位或整理排版：读[导航与排版](references/navigation-and-layout.md)。
- 高清图片/视频、图像分层、自动抠图：读[专用处理](references/specialized-processing.md)。
- 复用对话素材、节点内容或本地文件：读[素材](references/media-reuse.md)。
- 组装节点、连线、生成：读[执行](references/graph-and-generation.md)。
- 追问、文案与最终交付：读[交互](references/interaction-and-output.md)。
- 版本冲突、失败或未知结果：才读[恢复](references/recovery.md)。

用户通常不必选择模型枚举或提供节点ID。只询问真正阻塞的缺失信息，能从当前对话和工具取得的不要再索取。节点位置不等于依赖；在生成前核对真实连线和配置。任务状态由工具回执确认，不用旧图片冒充新结果。输出按用户目标组织，不默认打印内部ID/版本表格。

侧栏关闭不影响后台读写；不要因此要求用户打开或自动调用canvas_open来绕过错误。遇到实际占用、草稿、版本或服务故障时才按恢复章节处理。

只问当前画布ID时，简洁回复“当前画布 ID：[103334](dsh-resource://canvas/103334)。”，替换为已确认的真实ID；不附名称、版本或单独的资源地址。无可确认目标时先查询，不能编造。
