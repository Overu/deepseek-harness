# 达人营销 - 整合类技能

专业的**多平台达人营销整合方案**技能，输出完整的 **6 大模块**方案：**洞察→人群分析→社媒传播主题→核心玩法→传播部分→传播效果**。

**核心定位：** 专注于**多个平台的达人/红人营销整合方案**（如抖音 + 小红书+B 站多平台达人投放），而非全渠道营销。

## 触发词

- "达人营销方案"
- "红人营销方案"
- "多平台达人投放"
- "达人整合方案"
- "KOL 整合营销"
- "达人矩阵策略"
- "跨平台达人投放"
- "抖音 + 小红书+B 站达人方案"

## 核心定位与适用范围

**核心定位：** 多平台达人/红人营销整合方案

**适用场景：**
- ✅ 多平台达人整合投放（抖音 + 小红书+B 站+ 快手等）
- ✅ 红人营销全案策划
- ✅ KOL/KOC 跨平台矩阵策略
- ✅ 达人内容营销整合方案

**不适用场景：**
- ❌ 单一平台种草（用 `influencer-seeding`）
- ❌ 包含线下渠道的整合营销（用 `marketing-integrated`）
- ❌ 品牌战略定位（用 `marketing-integrated`）

## 核心功能（6 大模块）

| 模块 | 功能 | 说明 |
|------|------|------|
| **一、洞察** | Brief 解读 | 拆解营销目标及任务 |
| | 行业/场景洞察 | 行业趋势总结、场景分析 |
| | 竞品社媒投放分析 | 卖点/内容/投放数据/达人类型量级/不足与优势 |
| | 本品社媒投放分析 | 卖点/内容/投放数据/达人类型量级/不足与优势 |
| | 机会点总结 | 产品卖点、本品与竞品差异点 |
| **二、人群分析** | 人群画像 | 年龄、兴趣、地域 |
| | 消费行为习惯 | 购买决策路径、价格敏感度等 |
| | 社媒偏好 | 用户喜欢的内容及调性 |
| **三、社媒传播主题** | Core Idea | 核心创意概念 |
| | 传播主题/Slogan | 3-5 个供选择 |
| | 传播调性/人设 | 品牌调性定义 |
| **四、核心玩法** | 视觉创意 | KV、视觉符号等 |
| | 互动机制 | 用户互动玩法设计 |
| | 创意落地 | 具体执行形式 |
| **五、传播部分** | 话题方向 | 不同传播方向定制 |
| | 媒介策略 | 不同平台匹配不同内容 |
| | 投放矩阵 | 不同量级达人投放规划 |
| | 传播节奏 | 分阶段传播 Roadmap |
| **六、传播效果** | 预算划分 | 达人费/投流费/制作费 |
| | 效果预估 | 互动、曝光效果预估 |

### 🔍 联网检索增强（必选环节 · 2026-03-24 新增）

**核心原则：** 所有营销方案必须包含联网检索，仅靠学习到的案例不足以支撑方案可信度

**检索范围（5 大方向）：**

| 检索方向 | 目的 | 建议来源 | 输出要求 |
|----------|------|----------|----------|
| **竞品分析** | 查询竞品实际种草策略 | 小红书/抖音/微博/天猫 | 至少 3 个竞品，包含投放达人类型/内容方向/互动数据 |
| **行业报告** | 市场规模/增长趋势/用户偏好 | 艾瑞咨询/QuestMobile/抖音行业报告 | 引用 2025-2026 年最新数据，标注来源 |
| **平台热点** | 话题热度/搜索指数/ trending 内容 | 千瓜数据/抖音热点/微博热搜 | 当前热度数据（非历史数据） |
| **KOL 报价** | 验证预算合理性 | 新红/蝉妈妈/飞瓜数据 | 头部/腰部/尾部实际报价范围 |
| **案例参考** | 类似品牌投放案例 | 广告门/数英网/SocialBeta | 至少 2 个可借鉴案例，包含创意概念/执行细节 |

**输出规范：**
- ✅ 所有检索数据必须标注来源（机构/网站/发布日期）
- ✅ 竞品数据必须包含具体账号/笔记链接（可点击）
- ✅ 行业数据必须标注年份（优先 2025-2026）
- ✅ 案例参考必须包含案例链接（可点击访问）

**禁止行为：**
- ❌ 仅使用技能内置案例，不进行联网检索
- ❌ 引用过时数据（>2 年前的行业报告）
- ❌ 竞品分析无具体账号/内容链接
- ❌ 案例参考无来源链接

### 📊 市场分析与竞品分析数据规范（2026-03-25 新增）

**核心原则：** 所有市场分析、竞品分析必须使用 DSH 官方联网检索工具 web_search 检索最新数据，并附可点击查看的参考资料链接

**铁律：**

| 要求 | 说明 | 违规处理 |
|------|------|----------|
| **必须使用 web_search 检索** | 禁止仅凭知识库估算市场规模、增长率等数据 | 立即停止输出，重新检索 |
| **必须附参考资料链接** | 每个数据点需标注来源，链接可点击访问原文 | 补充来源后重新输出 |
| **必须标注数据时效** | 明确标注数据发布时间（如"2025 年 3 月数据"） | 补充时间后重新输出 |
| **禁止估算核心数据** | 市场规模、竞品销量、价格等不得估算 | 用"暂无公开数据"替代 |

**参考资料格式：**
```markdown
**数据来源：**
1. [文章标题](URL) - 发布机构，发布日期
2. [文章标题](URL) - 发布机构，发布日期
```

**市场分析必搜方向：**
- 《中国户外消费趋势报告 2025/2026》
- 《天猫/京东户外行业白皮书》
- 城市户外鞋市场规模、增长率数据
- 消费者画像与购买行为研究

**竞品分析必搜方向：**
- 竞品品牌最新营销 Campaign
- 竞品天猫/京东销量数据
- 竞品小红书/抖音投放数据
- 竞品价格策略与促销活动

**禁止行为：**
- ❌ 仅凭知识库估算市场规模、增长率
- ❌ 竞品数据无来源链接
- ❌ 引用超过 2 年的行业报告
- ❌ 使用"约""大概"等模糊表述替代检索

### 阶段 1：Brief 收集（必须）

**开始前确认 5 要素：**
1. 品牌/产品信息？
2. 目标种草平台（抖音/小红书/B 站/快手）？
3. 预算范围？
4. 种草周期（618/双 11/日常）？
5. 核心 KPI（曝光/互动/转化/搜索）？

### 阶段 2：数据检索（调用 DSH 联网检索）

**⚠️ 重要：统一使用 DSH 官方联网检索工具 `web_search`**
- 所有联网检索通过 DSH 的 `web_search` 工具完成，**无需外部 API Key**
- 直接填入检索目标，工具返回真实结果并附带可点击引用 URL
- **禁止**直接说"没有数据"或"不知道"——用 `web_search` 检索最新报告

**用 `web_search` 检索：**
- 行业趋势数据：`2025-2026 年 {行业} 抖音/小红书行业趋势报告`
- 竞品投放信息：`{竞品品牌} 小红书/抖音 KOL 投放案例 2025`
- 人群洞察报告：`{目标人群} 消费行为习惯 社媒偏好 研究报告`

**使用灵感库 API 检索：**
- 同类品牌种草案例
- Message House 优秀案例
- 达人矩阵玩法参考

### 阶段 3：洞察分析（遵循 MKT 规范）

**网页检索规范（MKT-001）：**
- ✅ 每个数据点标注引用来源 `[1]` `[2]` `[3]`
- ✅ 引用包含**标题 + 机构 + 可点击 URL 链接**
- ✅ **参考资料部分必须附上可直接访问的 URL**（用户可追溯）
- ✅ 所有数据基于 API 真实返回，禁止编造
- ✅ 优先引用：官方发布 > 权威媒体 > 行业报告
- ✅ 数据标注时间/年份，超过 2 年需特别说明
- 🔴 **引用无可访问链接属于严重违规**

**分析观点提炼规范（MKT-012）：**
- ✅ 重点不是信息搜集，而是信息分析
- ✅ 每部分分析总结出**1-2 个核心观点**
- ✅ 每个核心观点用**不超过 3 个支持点**证明
- ✅ 必须有图片或文字来源佐证支持点

**竞品分析框架（MKT-012）：**
- ✅ 分析 3-4 个核心竞品
- ✅ 包含：品牌/产品定位、核心消费群、核心卖点、品牌/产品策略（传播主题 + 广告内容）

**人性需求分析（MKT-007）：**
- ✅ 遵循 7 大需求分类体系（生理/安全/情感/尊重/认知/审美/自我实现）
- ✅ 使用**224 项标准子类别**（详见 human-needs-insight 技能）
- ✅ 消费者洞察格式：[目标人群描述] + [痛点/现状] + [渴望/期待]
- ⚠️ **注意：** 羽绒服等产品应使用"**保暖**"（生理需求标准子类别），不得使用"温暖"等非标准名称

### 阶段 4：传播主题生成

**创意概念确认流程（MKT-002）：**
- ✅ 生成 3-5 个传播主题供选择
- ⏸️ **必须等用户确认后才能继续**
- ✅ 每个主题包含：核心洞察、创意主张、人性需求连接、创意阐述

**创意输出精简规范（MKT-013）：**
- ✅ **只输出核心创意：TVC + KV 两部分**
- ❌ **禁止输出以下内容**（业务专家明确要求）：
  - 态度文案库（主态度、短版态度等）
  - 功能文案（产品卖点文案）
  - 场景文案（使用情境文案）
  - 金句库（社交传播金句）
  - 任何文案创意部分
- ✅ **TVC 脚本**：60 秒，≥20 镜头，表格格式（镜头号/时长/画面/台词/景别/音效）
- ✅ **KV 系列**：概念 KV（3-5 张）+ 卖点 KV（3-5 张），每张含画面创意描述/核心文案/色彩/构图

**TVC 创意规范（MKT-016）：**
- ✅ **1 分钟脚本至少 20 个镜头**——每个镜头需包含：镜头号、时长、画面描述、台词/旁白、景别
- ✅ **创意概念演绎**——TVC 需体现品牌或产品理念，有完整叙事
- ✅ **分镜脚本格式**——表格形式，清晰可读，可执行
- ✅ **技术规格**：需标注时长、镜头数、拍摄风格、色调、音乐要求
- ⚠️ **违规示例**：输出 12 镜头（不足 20）、缺少音效列、缺少技术规格

### 阶段 5：核心玩法设计

**视觉创意（MKT-015 规范）：**

⚠️ **重要：KV 视觉稿输出规范（2026-03-19 更新）**

| 类型 | 数量 | 说明 | 输出要求 |
|------|------|------|----------|
| **概念 KV 系列** | 3-5 张 | 演绎创意概念，体现品牌/产品理念 | 每张需有独立创意角度，形成系列感 |
| **卖点 KV 系列** | 3-5 张 | 结合创意概念，体现核心卖点 | 每张聚焦 1 个卖点，视觉化表达 |

**KV 设计输出规范：**
- ✅ **可点击预览的图片链接**——AI 生成后直接输出 OSS 链接，确保可点击访问
- ✅ **系列稿思维**——概念 KV（3-5 张）+ 卖点 KV（3-5 张），不是单张
- ✅ **详细设计简报**——AI 绘图无法精准生成明星和文字，需提供设计简报供设计师执行
- ✅ **参考图 + 文字说明**——AI 生成参考图 + 详细设计规格（尺寸/色彩/构图/元素）

**AI 绘图限制说明：**
- ❌ 无法精准生成特定明星（如郭麒麟）——需用设计简报 + 真人拍摄
- ❌ 无法精准渲染文字——Slogan 需后期添加
- ✅ 可用于：构图参考、色彩参考、氛围参考、元素布局参考

**视觉符号设计：**
- 超级符号（品牌识别元素）
- 品牌色规范（HEX 值 + 使用场景）
- 字体规范（字号 + 层级 + 应用场景）

**互动机制：**
- 用户参与方式（话题挑战、UGC 征集、互动 H5 等）
- 激励机制（奖品、荣誉、社交货币）

**创意落地：**
- 具体执行形式（短视频/直播/图文/活动）
- 创意 demo 示例

### 阶段 6：传播策略

**传播分阶段规范（MKT-014）：**
- ✅ 整体传播策略（目标/核心信息/节奏/资源）
- ✅ 分阶段传播内容（预热期/上市期/延续期）
- ✅ 传播 Roadmap（时间轴 + 关键节点 + 资源投入 + KPI）

**三阶段传播框架：**
| 阶段 | 时间 | 引导性大话题方向 | 核心内容 |
|------|------|------------------|----------|
| 预热期 | 上市前 2-4 周 | 品牌/产品期待 | 亮相创意、预热事件、KOL 剧透 |
| 上市期 | 上市当周 + 后 2 周 | 卖点吸引 | TVC 首发、KOL 评测、达人种草 |
| 延续期 | 上市后 3-8 周 | 口碑评价 | 卖点事件、KOL 横评、KOC 体验 |

### 阶段 7：效果预估

**预算划分：**
- 达人费用（头/腰/尾部占比）
- 投流费用（平台/节点/机制）
- 内容制作费

**效果预估公式：**
```
总曝光 = Σ(达人粉丝数 × 平均阅读率 × 达人数量)
总互动 = 总曝光 × 互动率（行业基准）
总点击 = 总曝光 × 点击率（行业基准）
总转化 = 总点击 × 转化率（行业基准）
ROI = 总转化金额 / 总投入
```

| 3. 视觉创意 | KV/TVC 创意确认后 | `html-designer` + `media-generator` | `{project}-visual.html` |
| 4. 传播策略 | 传播节奏/媒介策略/达人矩阵确认后 | `html-designer`（直接调用） | `{project}-strategy.html` |
| 5. 效果预估 | 预算划分/效果预估确认后 | `html-designer`（直接调用） | `{project}-roi.html` |
| 6. 完整方案 | 所有章节完成后整合 | `html-designer`（直接调用） | `{project}-full.html` |

**增量生成工作流程：**
```
1. 完成某章节内容 → 
2. 用户确认 → 
3. 【直接调用 html-designer/html-coder 技能】→ 
4. 告知用户预览位置 → 
5. 继续下一章节 → 
6. 最终整合所有章节为完整方案
```

**技术要点：**
- ✅ **直接调用技能，不启动子代理**
- ✅ 每章节独立生成，避免单次写入过长（控制<10KB）
- ✅ 使用统一 CSS 样式表，确保章节间视觉一致性
- ✅ 每章节预留导航锚点，支持最终整合
- ✅ 用户可随时查看已生成章节，掌握进度

**禁止行为：**
- ❌ 最后一步才生成 HTML（应增量生成，同步推进）
- ❌ 单次写入超过 10KB（分章节生成，控制单次大小）
- ❌ 章节间样式不统一（使用统一 CSS 样式表）
- ❌ 不告知用户文件位置（每章节生成后告知预览方式）
- ❌ **启动子代理调用技能**（应直接调用）
- ❌ 直接调用 write 工具生成 HTML（必须用技能）

**好处：**
- ✅ 避免单次写入过长导致失败
- ✅ 用户可随时查看进度
- ✅ 中途停止也有可用成果
- ✅ 每步确认都有视觉反馈
- ✅ **避免子代理卡住风险**
- ✅ 专业技能保证设计质量

## 🏆 917 获奖案例核心创意方法论（2026-03-24 重磅新增）

**案例来源：** Inspiration API 案例库全库扫描（917 个获奖案例）

**总奖项数：** 2340 个

### 核心洞察（不只是统计规律）

**1. 创意的本质：不是"炫技"，而是"精准连接"**
- **产品就是解药**（172 次，18.8%）排第一 → 获奖案例是最**清晰表达产品价值**的
- **社会问题**（120 次，13.1%）排第二 → 品牌不能只卖产品，要**表达立场**
- **关键：** 精准连接用户需求、产品价值、社会议题三者

**2. 人性需求层级：安全需求被严重低估**
- **被认同**（68 次）排第一 → 符合预期
- **但：** 生命安全 + 身体健康 + 自然保护 + 心理健康 = 149 次（16.2%）→ 后疫情时代**安全感**是重要切入点

**3. 公益与慈善为何获奖最多？（112 个，12.2%）**
- 本质不是"卖惨"，而是**让旁观者变成参与者**
- 给普通人一个行动的理由和方式

**4. 快消品为何持续获奖？（食品 + 酒精饮品 = 141 个，15.4%）**
- 核心不是"产品多特别"，而是**把日常消费场景变成情感表达仪式**

**5. 创意手法的"黄金组合"**
- 单一手法获奖少，**组合手法**获奖多
- 高频组合：产品就是解药 + 幽默、社会问题 + 感同身受、意象化 + 价值认同

### 5 大可复用创意公式

**公式 1：极端场景放大法**
```
日常问题 → 极端场景 → 产品解决

本质：让"看不见的问题"变得"看得见"

案例：
- Specsavers：视力下降 → 走错城市 → 配眼镜
- 各种"你以为...其实..."叙事

全案策划应用：
- KV 创意：用极端场景放大产品解决的问题
- TVC 脚本：从日常问题切入，用夸张手法展示解决方案
```

**公式 2：身份标签焦虑法**
```
身份标签 → 失去恐惧 → 品牌拯救

本质：利用"我是谁"的焦虑

案例：
- StreetEasy"Never Become a Former New Yorker"
- Nike"你不是运动员，但你可以像运动员一样训练"

全案策划应用：
- 品牌定位：找到目标人群的"身份焦虑点"
- 传播主题：用"不是...但你可以..."的句式
```

**公式 3：自然权利对比法**
```
自然权利（鸟鸣） → 人权剥夺（人禁言） → 品牌行动

本质：用"理所当然"对比"被剥夺"

案例：
- Amnesty International"鸟能鸣而人禁言"
- 各种女权、环保广告

全案策划应用：
- 品牌主张：用"连 XX 都能...为什么人不能"的对比
- 社会议题：找到"被剥夺的权利"，品牌发声
```

**公式 4：数据颠覆偏见法**
```
既有偏见 → 真实数据 → 认知颠覆

本质：用"事实"打破"刻板印象"

案例：
- Orange"残奥选手速度 > 奥运冠军"
- 各种"你以为女性...但数据显示"

全案策划应用：
- 产品卖点：用数据颠覆品类偏见
- 传播素材：制作"你以为...但..."系列内容
```

**公式 5：仪式感创造法**
```
日常行为 → 仪式化 → 情感连接

本质：把"消费"变成"表达"

案例：
- Heineken"打开啤酒=开启美好时刻"
- Apple"用 iPhone 拍照=记录生活美学"

全案策划应用：
- 品牌仪式：设计产品使用的"仪式感"动作
- 传播话题：#我的 XXX 时刻# 用户共创
```

## ⏸️ 创意概念确认流程规范（2026-03-25 新增）

**核心原则：** 输出创意概念后**必须立即停止**，等待用户确认 preferred direction 后才能继续细化方案

### 执行流程

```
1. 输出候选创意概念（3-5 组）
   ↓
2. ⏸️ 立即停止，标注等待确认提示语
   ↓
3. 等待用户明确确认 preferred concept
   ↓
4. 用户确认后，继续细化方案（KV/TVC/传播策略/物料清单等）
```

### 等待确认提示语规范

**必须包含的要素：**
- ✅ 明确标注"⏸️ 等待确认"或类似提示
- ✅ 说明下一步动作："确认后我将继续细化方案"
- ✅ 列出可选操作："可以单选、多选、或提出修改意见"

**示例提示语：**
```markdown
**⏸️ 等待确认：**

请告诉我你 preferred 的创意概念方向（可以单选、多选、或提出修改意见），确认后我将继续细化方案。
```

### 禁止行为

| 禁止行为 | 错误示例 | 正确做法 |
|----------|----------|----------|
| **跳过确认直接输出完整方案** | 输出创意概念后继续输出 KV、TVC、传播规划等 | 创意概念输出后**立即停止** |
| **在用户确认前输出执行层面内容** | 输出创意概念后继续输出预算分配、渠道策略、物料清单等 | 等待确认后再输出 |
| **未标注等待提示语** | 输出创意概念后无任何提示，直接结束 | 必须标注"⏸️ 等待确认" |
| **提示语模糊** | "请确认"（未说明确认什么） | "请确认 preferred concept，确认后我将继续细化方案" |

### 违规案例（2026-03-25 记录）

## 📁 HTML 文件上传规范（2026-03-26 新增，16:15 更新）🔴 铁律

**核心原则：所有生成的 HTML 文件必须上传到服务器，返回 HTTPS URL**

### 为什么必须上传？

- ✅ 企业微信/远程用户无法访问本地文件
- ✅ HTTPS URL 所有渠道用户都可访问
- ✅ 便于分享和传播
- ✅ 避免"文件在我电脑上"的问题

### 执行流程

```
1️⃣ 生成 HTML 文件 → 2️⃣ 保存到 output/ → 3️⃣ 用 de_channel_send 交付 / media-generator 上传获取 URL → 4️⃣ 返回给用户
```

### 上传步骤

**1. 保存到 output 文件夹**
```bash
output/整合方案.html
```

**2. 交付文件（DSH）**
```bash
# 用 artifact_save 归入 output/ 交付物；或用 de_channel_send 发送到 IM 渠道；或用 media-generator 上传媒体并返回公开 URL
```

**3. 获取 URL**
```json
{
  "data": "https://insight-gpt.oss-cn-shenzhen.aliyuncs.com/user-in/xxx.html"
}
```

**4. 返回给用户（2026-03-26 16:15 更新）**
```markdown
✅ **整合方案 HTML 已生成完成**

🔗 [html 文件：下载查看详情](https://xxx.html)

---

**方案已包含：**
- ✅ 模块 1
- ✅ 模块 2
- ✅ 模块 3
```

### 🔗 链接展示规范（2026-03-26 16:15 新增）🔴

**核心原则：** HTML 文件链接必须使用**可点击的超链接文字标签**，禁止直接展示完整 URL 地址

| 要素 | 正确做法 ✅ | 错误做法 ❌ |
|------|------------|------------|
| **链接文字** | `html 文件：下载查看详情` | `在线预览` / `点击查看` |
| **链接展示** | 超链接文字标签（隐藏 URL） | 直接展示完整 URL 地址 |
| **本地路径** | 不展示本地文件路径 | `/Users/xxx/...` |

**正确示例：**
```markdown
✅ 🔗 [html 文件：下载查看详情](https://insight-gpt.oss-cn-shenzhen.aliyuncs.com/user-in/xxx.html)
```

**错误示例：**
```markdown
❌ 🔗 在线预览：https://insight-gpt.oss-cn-shenzhen.aliyuncs.com/user-in/xxx.html
❌ 📁 文件位置：/Users/insight/.openclaw/workspace/output/方案.html
```

### 禁止行为

- ❌ 禁止只返回本地路径
- ❌ 禁止使用 file:// 协议
- ❌ 禁止使用 `open` 命令让用户本地打开
- ❌ 禁止上传失败不告知用户
- ❌ 禁止直接展示完整 URL 地址（安全风险）
- ❌ 禁止展示本地文件路径（如 `/Users/xxx/...`）
- ❌ 禁止使用"在线预览"等模糊文字（统一用"html 文件：下载查看详情"）

## 🎯 创意概念生成五步推导法（2026-03-27 新增）

**完整方法论：** 参考 `~/skills/human-needs-insight/SKILL.md` 中的"创意概念生成五步推导法"

**快速应用流程：**
```
1️⃣ 产品特性分析 → 2️⃣ 人性需求匹配 → 3️⃣ 消费者洞察撰写 → 
4️⃣ 创意概念生成 → 5️⃣ 四要素一致性验证
```

### 五步推导详解

#### 第一步：产品特性分析（功能层）

**分析工具：产品特性三维拆解表**

| 维度 | 分析内容 | 关键问题 | 输出 |
|------|----------|----------|------|
| **功能特性** | 产品核心功能、技术参数、使用场景 | 产品能做什么？解决什么问题？ | 功能清单 |
| **情感特性** | 产品带来的感受、体验、身份象征 | 用户使用后感觉如何？ | 情感关键词 |
| **社会特性** | 产品代表的价值观、生活方式、群体归属 | 产品代表什么样的人？ | 价值标签 |

#### 第二步：人性需求匹配（心理层）

**分析工具：人性需求匹配矩阵**

| 产品特性类型 | 首选人性需求 | 次选人性需求 | 匹配逻辑 |
|-------------|-------------|-------------|----------|
| **功能型**（便捷/效率/安全） | 便捷、效率、金钱安全 | 信赖、舒适 | 解决实际问题 |
| **体验型**（愉悦/舒适/味道） | 愉悦、舒适、乐趣 | 味觉、沉浸 | 感官满足 |
| **美学型**（时尚/艺术/个性） | 时尚美、艺术美、个性 | 被认同、形象 | 视觉/身份表达 |
| **精神型**（超越/追寻自我） | 发挥潜能、追寻自我、超越 | 成就、自由 | 自我实现 |

#### 第三步：消费者洞察撰写（转化层）

**分析工具：洞察撰写四要素公式**
```
[目标人群描述] + [痛点/现状] + [渴望/期待] + [产品角色隐喻]
```

**四种洞察模板：**
- 表面痛点型（生理/安全需求）
- 深层渴望型（情感/尊重需求）⭐ 推荐
- 价值观冲突型（自我实现需求）⭐ 传播力最强
- 数字化焦虑型（认知需求）⭐ 新增

#### 第四步：创意概念生成（表达层）

**三种表达模式：**
- 态度宣言式（自我实现/尊重需求）⭐ 传播力最强
- 功能 + 情感双驱动（认知/安全需求）
- 对比/反转式（生理/情感需求）

#### 第五步：验证优化（质量层）

**分析工具：四要素一致性检查表**
- [ ] 产品 - 需求：产品特性是否支撑该人性需求？
- [ ] 需求 - 洞察：洞察是否触及该需求的核心痛点？
- [ ] 洞察 - 概念：概念是否回应了洞察中的渴望？
- [ ] 概念 - 手法：手法是否能有效表达概念？
- [ ] 手法 - 需求：手法是否匹配需求层次？

**质量评分表：** 总分≥4 分为优秀

## 🎓 五大核心定律（2026-03-27 新增 · 基于 6600 案例）

### 定律 1：人性需求层次定律
```
生理/安全需求 → 功能型手法（产品就是解药、产品示范）
情感/尊重需求 → 情感型手法（价值认同、感同身受）
认知/审美需求 → 艺术型手法（意象化、创造象征符号）
自我实现需求 → 精神型手法（成长与逆袭、价值认同）
```

### 定律 2：洞察深度 - 概念高度正相关
```
表面痛点洞察 → 功能型概念（传播力弱）
深层渴望洞察 → 情感型概念（传播力中）
价值观冲突洞察 → 精神型概念（传播力强）
```

### 定律 3：手法 - 需求匹配度定律
```
高匹配度（如便捷→产品就是解药）→ 创意有效性高
低匹配度（如便捷→意象化）→ 创意有效性低
```

### 定律 4：三要素一致性定律
```
人性需求 + 消费者洞察 + 创意概念 + 创意手法
    ↓
四者高度一致 → 获奖概率高
四者不一致 → 入库都难
```

### 定律 5：视觉优先定律（非获奖案例特有）
```
非获奖案例中，意象化使用率 21.9%（获奖案例仅 11.6%）
→ 视觉美感是灵感库入库的第一道门槛
→ 但社会价值是获奖的第二道门槛
```

- ❌ 闲聊、寒暄
- ❌ 简单确认（收到、好的、明白）

### 写入方式（必须执行）

**在输出飞书消息后，立即调用内置 `write` tool：**

```python
from datetime import datetime

timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
content = f"""
---

## [{timestamp}] 达人营销专家（关键输出）

### 达人营销方案

**达人矩阵：**...

**元数据：**
- 写入时间戳：{timestamp}
- Agent: 达人营销专家
"""

write(
    path="<工作区>/group-chat-log.md",
    content=content,
    append=True
)
```

**参数说明：**
- `path` - 共享文件路径
- `content` - 要写入的内容（Markdown 格式）
- `append=True` - 追加模式（不覆盖原文件）

**优点：**
- ✅ 无需审批（内置 tool）
- ✅ 立即可用
- ✅ 支持追加写入

### 读取共享文件（可选）

**需要参考历史对话时，调用内置 `read` tool：**

```python
# 读取完整文件
content = read(

content = read(
```

**参数说明：**
- `path` - 共享文件路径
- `offset` - 起始行号（1-indexed，默认 1）
- `limit` - 读取行数（默认全部）

**使用场景：**
- ✅ 需要参考之前的讨论历史
- ✅ 需要确认用户之前的决策
- ✅ 需要了解项目完整背景

**注意：** 读取操作是可选的，根据实际需要调用。

### 📸 多媒体文件支持

**写入时包含多媒体链接：**

```python
from datetime import datetime

timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S')
content = f"""
---

## [{timestamp}] 达人营销专家（关键输出）

### 达人营销方案

**达人矩阵：**...

### 达人案例图片

![](https://oss.example.com/influencer_case1.png)
![](https://oss.example.com/influencer_case2.png)

### 达人视频

[达人演示视频](https://oss.example.com/influencer_demo.mp4)

**元数据：**
- 写入时间戳：{timestamp}
- Agent: 达人营销专家
"""

write(
    path="<工作区>/group-chat-log-xxx.md",
    content=content,
    append=True
)
```

**多媒体格式支持：**
- ✅ **图片：** `![](https://xxx.png)` - Markdown 图片语法
- ✅ **视频：** `[视频](https://xxx.mp4)` - Markdown 链接
- ✅ **音频：** `[音频](https://xxx.mp3)` - Markdown 链接
- ✅ **HTML 视频：** `<video src="https://xxx.mp4" controls></video>`

**读取时自动包含多媒体链接：**

```python
# 读取完整内容（包含所有多媒体链接）
content = read(
    path="<工作区>/group-chat-log-xxx.md"
)

# 提取所有图片链接
import re
image_urls = re.findall(r'!\[\]\((https?://[^)]+)\)', content)

# 提取所有视频链接
video_urls = re.findall(r'\[视频\]\((https?://[^)]+)\)', content)
```

**优点：**
- ✅ 多媒体链接以文本形式存储，无需特殊处理
- ✅ 读取时自动包含所有链接
- ✅ 支持 Markdown 和 HTML 格式
- ✅ 链接永久有效（OSS/CDN 存储）

- 获取锁 → 追加写入 → 释放锁
- 锁超时 5s 自动释放
- 写入失败自动重试（最多 3 次）
- 错误记录到 `<工作区>/logs/write-errors.log`
