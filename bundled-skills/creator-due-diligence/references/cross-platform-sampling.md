# 跨平台覆盖、扩样与证据充分性

完整合作背调必读；用户限定平台或只问局部问题时按其范围执行。采样目标用于安排工作量，不是总体代表性或无风险保证。不能为凑数量重复抓相同内容。

## 1. 账号盘点先于作品采样

国内基准平台：抖音、小红书、微博、B站、快手、微信视频号、微信公众号、知乎。逐个平台搜索本名、已核实昵称/旧名和官方主页线索；有官方互链时沿链接核对。存在海外业务或已知海外账号时增加相应平台。

每个平台在 `account_inventory` 中有记录，即使没有取得账号。检索状态为 `checked / partial / unavailable / not_run`，候选账号身份为 `confirmed / candidate / excluded`。没有搜索结果写“本次未检出”，不能写“没有账号”；接口失败写获取失败。排除的粉丝号、搬运号保留排除依据。

账号至少记录平台、稳定ID、主页、昵称、身份状态/证据、公开活跃时间、是否纳入采样与原因。跨平台合并需已确认账号互链、官方声明/名录或用户确认；平台认证需明确对应本次人物并有归属佐证。同名、相似头像、相同搬运视频只生成候选。团队/工作室账号与本人账号分别保留其归属类型。

所有已确认本人公开账号进入采样计划。近一年活跃、项目相关或存在待核事件的账号优先深入；不活跃账号至少查看可见历史与合作线索，不能直接省略。平台不可取、账号身份待核、预算不足分别记录；无需等到八个平台都可取才继续其他部分。

## 2. 分层采样目标

| 来源 | 首轮工作量目标 | 必须覆盖的差异 |
|---|---|---|
| 主要活跃本人账号 | 每平台30–50篇作品元数据；可见作品不足时全取 | 近12个月按时段分布；普通/品牌、相关品类/其他主题、高互动/常规 |
| 本人作品评论 | 每平台10–20篇作品，每篇争取50–100条去重主评论 | 时间排序与热门排序分别留样；普通与品牌作品分层 |
| 次要/不活跃本人账号 | 先取可见近期与代表历史，按相关性扩展 | 旧合作、关键事件时段、其他平台未出现的内容 |
| 第三方公开讨论 | 跨平台争取20–50篇不同原始帖子/报道；实际量记录在采样与覆盖字段 | 中性评价、使用经历、具体异议、事件回应和后续；不预设负面配额 |
| 合作品牌官方内容 | 对与本次品类和竞品有关的合作逐项核对 | 原始官宣、具体产品、时间和合作身份；评论作为品牌号单独一层 |

以上目标可按实际活跃平台数、发布量和授权预算调整，并在 `sampling_plan` 保留目标、实际与差额原因。近12个月是首轮默认窗口；已知重要事件/合作向前追溯2–3年或原始发生时间。明确要求更长历史时遵循用户范围，不能把时间窗口写成已完成范围。

评论优先扩大不同作品和来源的覆盖，再深入单条作品。先沿真实游标翻页；重复页或重复游标且无新增时停止该分页链，改取其他作品。接口只支持默认排序则标为 `default_unknown`，不能虚构最新评论/热门样本；精选入口单列。楼中楼用于补关键异议、作者回应或上下文，保留主楼关系，不与主评论混作同一情绪分母。

正文/媒体审阅：项目相关的竞品合作、本品对比及疑似高风险作品优先取得全文或完整媒体。ASR/OCR只能处理合法可访问的内容，保留出处、时间点和识别置信度；不能以标题推断口播。媒体无法访问时在结构化记录中保留限制，并继续公开文本和评论采样。

## 3. 达人账号外的公开支持材料

在本人评论区之外，检索第三方社媒帖子、公开体验长文、品牌官方内容、可追溯媒体报道。涉及具体事件，再核对相关官方通报、当事人回应和后续。搜索摘要只作线索，重要结论尽量回到原文。

以来源原帖/通稿/截图建立 `origin_cluster_id`，记录发布主体 `publisher_key` 与关系 `self / partner / third_party / authority / unknown`。同一原文在多个平台转载计一次原始来源，传播条数另计。同一账号的多篇帖子不是多个独立发布主体；不把粉丝号或品牌号默认当成独立补证。

同文重复另建 `text_cluster_id`，仅标记重复现象，不自动判定水军。公开评论者的ID只在确需去重时受控保留，证据册不展示其主页、头像、IP或无关个人资料。自称买过的留言标“购买/使用自述”，不认定真实买家或成交。

## 4. 按判断检查证据是否够用

每个重要判断在 `evidence_adequacy` 中列 `claim_id`、实际主张、证据ID、平台数、不同作品数、相关去重评论数、原始来源数、发布主体数、实际时间窗、反证/回应状态，以及 `supported / limited / insufficient / not_assessed` 和理由。独立性未核实的来源不填“独立来源数”，该值用 null；原始来源数和发布主体数可以客观计算。

| 判断类型 | 足以支持的材料 | 应收窄或补采的情况 |
|---|---|---|
| 某次品牌合作确实公开发生 | 身份匹配的品牌官宣或明确合作记录 | 一条有品牌的文案只能确认露出；合同有效期仍需合同证据 |
| 用户在样本中有哪些反馈 | 不同作品的原评论，分清对象、主题和来源层，给例证与反例 | 只有本人评论区、精选/单一排序或单篇作品时限定样本，不写整体口碑 |
| 跨平台口碑判断 | 主要已确认账号均有结果或缺口记录，同时有第三方讨论；按平台分别解释 | 多平台转载同一事件、同一粉丝群刷屏、相关评论极少时仍为 limited |
| 发生具体不当行为 | 与本人匹配的原始材料、上下文、回应/后续，及适用的独立补证/处理结果 | 未证实指控与转载数量不能升级成事实；严重结论需人工复核 |
| 风评变化趋势 | 相同平台、来源层、排序和可比时间窗的样本 | 旧作品下的新评论、两次不同默认排序不能证明趋势 |

“达到目标数量”与“支持结论”是两件事。一份明确原始官宣可以确认一次合作；数千条混合、无关或重复评论也不能证明没有风险。评论数量之外，同时检查非空文本、评价对象明确数、可判定数和来源集中程度。

## 5. 预算与结束条件

先验证每条新路线一页，再投入扩样；本次预算包括探测、失败及不确定计费请求。低预算优先次序：账号核验→不同平台/作品→第三方原始材料→评论分页→关键回复。额度不够则降低目标、保留缺口；无授权不得为达标续费。

逐层结束原因使用实际事实：`target_reached / source_exhausted / budget_exhausted / route_unavailable / identity_unresolved / repeated_cursor / user_scope`。目标达成但关键线索仍待核时，只在剩余预算与已授权范围内定向追加。资料不足不能以“未发现”替代获取失败。

## 6. 面向业务的交付

主报告每维1–2句给出事实、合作风险与必要动作，并链接代表证据。具体缺失项阻止签约时，将它写成有负责对象和确认动作的签约事项。`evidence.md` 保留账号资料、代表原文、回应和来源；`due-diligence.json` 保留客观覆盖、去重计数、采样差额、技术限制与调用台账。报告结构以[报告契约](report-contract.md)为准，不另加采样范围或方法说明章节。
