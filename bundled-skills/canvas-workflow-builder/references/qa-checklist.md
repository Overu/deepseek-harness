# 交付前自检清单

> 什么时候读：建完准备运行前（A0/A 段）、真实出图/配音后交付前（B 段）、处理类交付前（B'' 段）、异常恢复后（R 段）、以及任何涉及电商文案时（C 段）。
> 用法：逐条打勾；任一条不过就回到对应阶段修，不要"先交付再补"。

## A0. 运行闸门（在一切 `canvas_run` 之前，3 条）

| # | 检查项 | 判据 |
|---|---|---|
| A0-1 | **用户明确说了"运行"** | 原话里有"运行/跑吧/开始/生成吧"之类明确指令；"帮我做个 XX"、"先搭个流程"**都不算** |
| A0-2 | 确认范围覆盖本次提交 | 用户确认过的节点集合、模型、分辨率、时长、条数与这次 `canvas_run` 完全一致；有变动就重新问 |
| A0-3 | 成本与量已告知 | 已经告诉用户：几张图 / 几条视频 / 几条 TTS、什么模型档位、大概多久；数量过闸门（>30 图 / >6 视频）时更要明说 |

> 这三条没过，就**不要**调用 `canvas_run`——把「待运行清单」交给用户等回复。每次运行都计费，返工更贵。

## A. 建图自检（18 项，全部通过才能开始 `canvas_run`）

| # | 检查项 | 怎么查 | 不过怎么办 |
|---|---|---|---|
| A1 | 节点数与计划一致 | `canvas_get(view:"graph")` 对照 `plan.json` | 补建或删多余节点 |
| A2 | 每条边真实存在且方向正确 | graph 的 `edges[]` 逐条比对 | `canvas_edges(ops:[add])` 补，或 `edit` 改接 |
| A3 | 每条边落在允许矩阵内 | 查 `connection-rules.md` §1 | 改接端口；无法成立就改结构 |
| A4 | 生成节点参数与实时目录一致 | `canvas_get(view:"nodes")` 看 `params/seniorParams` | `configure` 修正 |
| A5 | 参数名都是新名 | 检查有无 `times/image_size/ratio/seconds` | 改成 `gen_count/resolution/aspect_ratio/duration` |
| A6 | 模型/modelType 来自实时目录 | 与 `canvas_models`（image/video/audio）比对 | 重读后 `configure` |
| A7 | **模式与入边匹配（模式门）** | `text_to_image` 有图边？`reference_image_to_image` 0 图？ | 先 `configure` 定模式；看 `warnings` 补配置 |
| A8 | 素材节点 URL 非空且来自真实节点 | `canvas_get(view:"nodes")` 看 `outputs` | 重新导入；不得拿本地路径/附件 ID 顶替 |
| A9 | 视频/音频素材已导入并读回 | 同上（四类来源见 `media-intake.md`） | 按来源分支导入；没有来源才请用户补文件 |
| A10 | 文本节点内容就位 | copy 看正文；llm 看指令。**TTS 台词直写 audio 的 prompt 时，不需要也不该再建 text 节点** | 补写；llm 必须登记 `manualSteps` |
| A11 | 生成节点提示词自包含 | 遮住上游文本，只看该节点提示词能否独立生成 | 补全画幅、主体、锁定表述 |
| A12 | 人工步骤已明确 | `manualSteps` 覆盖**所有有入边的 text 节点**、必要音色选择、音乐生成 | 补登记并在交付里说明 |
| A13 | 无越权痕迹 | 无 group/工具节点/模板/整图调度 | 改受支持结构 |
| A14 | 坐标来自布局算法 | 序列类（≥12 节点或 ≥3 条镜头/套图）是否用 `layout_plan.py --lanes`；单图是否用默认模式；9:16 是否按 711 高留距 | 重排（建完后不能拖单个节点，只能删了重建） |
| A15 | **无孤立节点** | 每个节点都出现在 `edges[]` 里（`check_complete.py --graph` 的 K8） | 删掉，或接到上游/下游；输入节点必须有出边 |
| A16 | **卡片不重叠** | `canvas_get(view:"nodes")` 的 `position`+`size` 两两不相交（K9） | 按新坐标删了重建；`canvas_layout` 只适合小图 |
| A17 | **待上传素材有入口节点** | 用户将提供的产品图/参考视频/Logo 是否已有「xx｜待上传」节点，且**已连下游边**、下游按"将有素材入边"配好模式 | 补建槽位 + 补边 + 改模式 + 登记 `manualSteps`；空槽不算孤立节点，但**不能没有出边** |
| A18 | **左→右、同镜同行** | 每条边 `target.x > source.x`；同一镜/同一套图的旁白/分镜/成片 y 相同；一眼能看出流程走向 | 按 `--lanes` 重新生成坐标，删了重建 |

> `validate_plan.py` 覆盖了 A3/A5/A6(计划层)/A10/A11/A12/A15/A16 的离线部分（R22/R23/R24）；
> `layout_plan.py --lanes` + `tests/test_layout_lanes.py` 覆盖 A14/A18 的坐标层；但不能替代 A1/A2/A4/A7/A8/A9/A17 的真实画布核对。

## B. 出图自检（7 项，逐张过）

| # | 检查项 | 判据 |
|---|---|---|
| B1 | 主体一致性 | 商品/人物造型、颜色、logo、材质与参考图一致；无变形缺件 |
| B2 | 文字正确 | 标题/卖点/价格/CTA 无错字、无乱码、无多余占位（如 "LOGO" 字样） |
| B3 | 版面合规 | 文字不被裁切，重要信息距边缘 ≥5% |
| B4 | 层级清晰 | 商品是视觉焦点，装饰不压过主体 |
| B5 | 尺寸正确 | 画幅比例与分辨率符合交付要求（用产物真实尺寸核对） |
| B6 | 结果归属正确 | 交付的是**本次** run 的真实 `outputs` |
| B7 | 用途匹配 | 与用户声明的平台/用途一致 |

不合格时**一次只改一个变量**：文字错 → 提高文字权重/换 `gpt-image-2` high；商品变形 → 强化主体锁定；
画面脏乱 → 简化背景；文字始终不稳 → 先出无字底图再叠字。

## B'. 执行完整性（4 条，跑完才能交付）

| # | 检查项 | 判据 |
|---|---|---|
| E1 | `runs[]` 每个节点都 done | 有 `outputs` 才算；`submitted`/`paused` 不算 |
| E2 | 未完成的必须说清原因与断点 | 哪个节点、什么错误码、下一步怎么解 |
| E3 | 批量 `paused` 已续跑 | 用 `nextIndex` + 最新 confirmed 版本续；不把前缀交付当全部 |
| **E4** | **下游文本节点已运行** | 有上游入边的 `text` 节点正文非空（K10）；为空说明它还没跑 —— agent 跑不了，请用户运行后再跑下游，禁止拿空文本硬跑 |
| **E5** | **按分支推进、逐条核对上游产物** | 目标节点每条入边的来源都要就绪（image/video 有 `outputs`、audio 已 completed）；**不同分支互不等待**（a 分支可跑到第 4 个节点、b 分支还在第 2 个），同一条分支内必须上游收终态再提交下游；回执出现「需要连入图像」= 这条入边的上游还没产物（规则 24 / R26） |

## B''. TTS / 专用处理（5 条）

| # | 检查项 | 判据 |
|---|---|---|
| P1 | TTS 有真实音频产物 | `outputs` 是可播放音频 URL；不是旧产物。**台词直写 prompt 时 `prompt` 非空即可，不要求 text 入边**；两种来源不要重复写 |
| P2 | 音色与参数合法 | `voiceId` 来自 `view:voices`；`seniorParams` 在 `seniorParamHints` 范围内（`speed` step 0.1，别写 0.95） |
| **P6** | **视频真用上了上游音频** | 视频 prompt 第一段必须声明「使用连入的图片N和音频N…音频N是音轨，原样使用」（规则 23 / R25）；跑完用 `ffprobe -show_streams -select_streams a` 确认有音频流、`ffmpeg -af volumedetect` 确认非静音；有流没人声 = prompt 仍未生效 |
| P3 | 处理可用性已确认 | `canvas_capabilities` 的 `available:true`；不可用如实说明 |
| P4 | 处理结果节点已接入 | 后续生成连 `outputNodeIds` 的结果节点，不用原图冒充 |
| **P5** | **配音有下游、音画关系在图里** | 旁白节点要么经 `audio_source→audio_target` 接到对应镜头（且视频已切 `reference_image_to_video`、`duration` ≥ 该句时长），要么在交付里明说"独立音轨、画布未合成"。**禁止**"画布内 TTS 无下游 + 画布外混音"还宣称画布已成片（2026-10-20 真实踩过） |

## C. 电商与广告合规红线（触及即拦，改文案而不是改图）

| 类别 | 禁止/需谨慎 | 替代写法 |
|---|---|---|
| 绝对化用语 | 最、最好、最强、第一、唯一、顶级、国家级、100%、绝对 | 可核实描述：如"2026 新款"、"316 不锈钢内胆" |
| 功效宣称 | 治疗、根治、7 天见效、永久 | 只描述成分/工艺/使用感受 |
| 数据与参数 | 未经确认的加速、续航、成分含量 | 标注来源；无法核实则不写 |
| 品牌与商标 | 未授权 logo、明星肖像、他人素材 | 提示用户确认授权；未确认不商用 |
| 价格与机制 | 编造原价、虚假折扣 | 价格/机制必须由用户提供 |
| 平台规则 | 各平台另有禁用词表 | 交付时提示用户按投放平台复核 |

## F. 画布完整性门（`scripts/check_complete.py`）

| # | 检查项 | 判据 |
|---|---|---|
| K1 | 每个生成节点都有真实产物 | `outputs` 非空；image/video/**audio** 都算生成节点 |
| K2 | 每个文本节点都有内容 | 正文或 LLM 指令至少一个非空 |
| K3 | 没有占位/待上传节点 | 标题含 待上传/占位/TODO 且无内容 |
| K4 | 没有内部逻辑节点 | 自检/清单/旁注/说明/话术 一律不该在画布 |
| K5 | 没有孤立节点 | 无入边无产物且不是边端点 |
| K6 | 画布名与实际节点数一致 | 名字写"7 节点"实际 6 个 → 改名（工具不支持重命名时如实在交付说明） |
| K7 | 节点数与计划一致 | `--expect-node-count` |
| K8 | 没有孤立节点 | 一条边都没有（需 `--graph`；单节点画布除外）→ ERROR |
| K9 | 卡片不重叠 | `position`+`size` 矩形相交 → ERROR，用 `canvas_layout` 重排 |
| K10 | 下游文本节点已运行 | text 节点有入边但正文为空 → ERROR，需用户在画布内运行 |

## R. 连接或未知结果恢复（仅出现异常时检查）

执行细则见 [connection-recovery.md](connection-recovery.md)。

| # | 检查项 | 判据 |
|---|---|---|
| R1 | 恢复证据来自故障后 | 标注最近 nodes/graph 真实回执；summary 或故障前读取不冒充当前 Client 正常 |
| R2 | 自动恢复有界 | 同一故障默认60秒/最多3次只读探测，包含已耗时；明确未生效的业务操作最多恢复重试1次；耗尽即保存断点 |
| R3 | 探测没有业务副作用 | 原画布 nodes + refresh:false；未通过创建、编辑、生成、导入、处理或打开画布试连接 |
| R4 | 未知项沿原请求核验 | 保留 requestId/jobId/taskId；矛盾回执按未知处理；未以无新Job或旧outputs判定未提交 |
| R5 | 成功项与用户改动受到保护 | 不重放 completed 前缀；最新 confirmed 版本与目标内容一起核对，不直接换版本覆盖 |
| R6 | 续跑符合原授权 | 仅搭建时不顺手生成；原运行授权不扩展为重跑/扩量/换模型 |
| R7 | 交接与日志描述准确 | 如实说明完成项、阻塞项、最近事实和断点；不臆断网络/切页原因，不自动刷新/重启或读取凭据 |

## D. 交付话术自检（4 条）

1. 只说**真实完成**的内容（没把"已提交"说成"已完成"）。
2. 说明人工步骤（T1 生成、必要音色选择、音乐边界）。
3. 给出打开方式与复现方式（画布 ID / 需重跑节点）。
4. 不倾倒内部 ID/版本/枚举（用户要求验收证据时才给）。
