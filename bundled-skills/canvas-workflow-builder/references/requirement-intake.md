# 需求解析（S0）：七要素、反问话术、素材分工

> 什么时候读：接到一个画布/批量生成需求，准备写 `plan.json` 之前。
> 目标：把口语需求变成结构化 `brief`，并且**只问真正阻塞的问题**。

## 1. 七要素清单（缺一不可，缺的要么问、要么给默认并标注假设）

| # | 要素 | 要抽出来的东西 | 缺失时的默认策略 |
|---|---|---|---|
| 1 | **交付物** | 类型（图/视频/文案）、数量、是否需要成品（还是只要骨架） | 数量不给 → 默认 1；"做一张/一批"必须问清数量 |
| 2 | **平台与尺寸** | 画幅比例、分辨率/清晰度、用途（主图/详情页/信息流/封面） | 电商主图默认 `3:4`；列表图 `1:1`；信息流/短视频 `9:16`；分辨率默认按目录默认值，不擅自拉满 |
| 3 | **数量** | 每个交付物的张数/条数 | 默认 1；>30 图或 >6 视频必须先走官方确认 |
| 4 | **风格调性** | 风格关键词、主色/辅助色、参考调性 | 可按上下文取合理默认并**一句话说明**（官方 guidance 允许） |
| 5 | **素材** | 有哪些图/视频/音频；各自用途；**谁上传** | 无素材 → 走纯文生图/文生视频（`allowNoInput`） |
| 6 | **文字内容** | 标题、卖点、价格、CTA、活动机制 | **不得编造**（价格/参数/功效/认证）；缺失就用中性创意文案或留白 |
| 7 | **合规约束** | 平台规则、广告法、品牌授权 | 默认带：无绝对化用语、不编造功效、logo 需授权 |

## 2. 素材分工（必须在 S0 就定，不能拖到建图时才发现做不了）

| 素材 | 谁能上传 | 落地方式 | 必须在 plan 里写成 |
|---|---|---|---|
| 图片（用户发的图） | agent | `canvas_asset_import` + `source.type=attachment` | `assets[].uploader=agent, source=attachment` |
| 图片（本会话 AI 刚生成的图） | agent | `canvas_asset_import` + `source.type=conversation_asset` + `assetRef` | `source=conversation_asset` |
| 图片（画布上已有的产物） | agent | `canvas_asset_import` + `source.type=canvas_node` + `nodeId/outputIndex` | `source=canvas_node` |
| **视频 / 音频（附件/会话生成/工作区）** | **agent** | `canvas_asset_import`（`attachment` / `conversation_asset` / `workspace_file` / `canvas_node`），读回 URL 后接入 | `uploader=agent, source=attachment/conversation_asset/workspace_file` |
| 视频 / 音频（只有用户手里有） | 用户 | 请用户把文件发到会话或放进工作区，再由 agent 导入 | `uploader=user, source=user_upload` + `manualSteps` |

一句话原则：**四类素材我都能导入，优先让你把文件发到会话/工作区；只有来源确实不在我这儿时才请你补。**

## 3. 一次性反问模板（≤5 问，集中问，不逐字段挤牙膏）

只在下列情况问：① 素材指代不明（多张图分不清用途）；② 关键用途确实影响产出（要不要写字、要不要真人）；
③ 必要前置缺失（要成品但没有任何商品图）；④ 数量影响成本闸门；⑤ 合规敏感（功效/价格/品牌）。

可直接复用的话术：

```
在开始搭之前，确认 4 件事就够（其余我按默认来）：
1. 交付物数量与尺寸：一共几张？用什么画幅（3:4 主图 / 1:1 列表 / 9:16 信息流）？
2. 素材：你给的这几张图分别是做什么用的？（商品图 / 模特图 / 参考风格图）
3. 画面文字：标题、卖点、价格分别写什么？（这几个我不编造）
4. 合规：有没有平台或品牌方的禁用词/授权限制？
```

**不要问**：模型枚举、节点 ID、技术参数键名、画布 ID（这些本该由你决定或从工具读取）。

## 4. 结构化 brief（写进 `plan.brief`；也是喂给文本节点 LLM 的标准输入格式）

官方模板库的输入节点用五段式，可直接沿用：

```
一、基础信息
产品名称：xxx　品牌名称：xxx　产品类别：xxx

二、核心价值（选填）
核心卖点：1、… 2、… 3、…
功能亮点：1、… 2、… 3、…

三、应用场景与目标用户（选填）
使用场景：1、… 2、…
目标人群：xxx

四、风格与情感表达（选填）
产品风格：xxx　感性联想：xxx

五、生成控制参数
推广平台：xxx　文案风格：xxx（软广/硬广/测评/口播）
```

电商短版（4 行即可）：`品牌名称 / 产品类型 / 产品亮点 / 核心卖点`。

## 5. 需求 → 原型的快速判定（写完 brief 立刻做）

| 需求特征 | 原型 |
|---|---|
| 一张素材图 → 多张不同版式/尺寸 | A1（fan-out） |
| 素材图 + 要写卖点/价格文字 | A2 |
| 要多张"统一又有差异"的系列图 | A3 |
| 要在一张图上继续改（换背景/换色/放大） | A4 |
| 素材图 → 一条短视频 | A5 |
| 先有文案脚本 → 再出视频 | A6 |
| 一份 brief → 多平台多风格文案 | A7 |
| 文案 → 配音 | A8 |
| 多角度展示 | A1 替代 A9（多角度提示词 + fan-out） |
| 视频输入 → 复刻/换装 | A10 |
| 图 → 图 → 视频全链 | A11 |

详见 `references/archetypes.md`；电商场景反查见 `references/ecommerce-patterns.md`。

## 6. 交付前的自问（写完 brief 立刻自检）

1. 每个交付物都能在 `nodes` 里找到对应的产出节点吗？
2. 每份素材都标了"谁上传、落到哪个节点"吗？
3. 有没有我编造的事实（价格、参数、功效、认证、品牌关系）？
4. 数量有没有触发 >30 图 / >6 视频的确认闸门？
5. 该人工的步骤（T1 文本节点、视频/音频上传、文本模型选择）都进 `manualSteps` 了吗？

## 7. 运行确认（建完必须做，不能省）

搭完就是"交付待运行清单 + 等确认"这一步，**不要顺手跑**。清单按这四项写，短而具体：

```
【已搭好】<画布名/ID>，共 N 节点、M 条边
【参与生成】图 ×A（<模型>/<画幅>/<分辨率>）｜视频 ×B（<模型>/<时长>/<分辨率>）｜配音 ×C（<音色>/<语速>）
【人工步骤】<T1 文本节点需你点运行 等>
【预计】约 X 分钟；如需改脚本/画风/条数，现在改最省
要我运行吗？回复"运行"即可。
```

判定「用户已经确认」的唯一标准：**原话里出现明确的运行指令**（"运行""跑吧""开始""生成吧"）。
- "帮我做一张海报" = 目标描述，不是运行授权。
- "先搭个流程 / 我看看结构" = 只搭不跑。
- 用户提了修改意见 = 改完**重新**问，不要"顺手跑一下"。
- 一次授权只覆盖当次的节点与参数；加量、换模型、重跑都要再问。
- 唯一例外：用户在同一句话里既给了目标又明说"直接跑 / 跑起来 / 生成吧"，才可以一次做完。
