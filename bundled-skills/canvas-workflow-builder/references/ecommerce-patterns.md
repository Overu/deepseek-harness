# 电商场景映射（Ecommerce Patterns）

**解决什么问题**：电商需求（主图、促销海报、详情页、套图、试穿、拆解、复刻…）该套哪条官方模板的思路、用哪个原型、参数怎么配。
**什么时候读**：需求里出现"主图 / 头图 / 详情页 / 大促 / 促销 / 卖点 / 套图 / 复刻 / 试穿 / 平铺 / 种草"这类词时；写 `plan.json` 前配合 `archetypes.md` 一起看。
**口径**：官方 130 条模板中 **81 条有完整图 JSON（可解析）**、**49 条被 Excel 单元格 16KB 截断（不可解析）**。本文档中每条映射都标注了证据属于哪一类；**截断模板只能当"官方做过这类产物"的存在性证据，不能当结构证据**（清单见 §4）。原型编号与 `archetypes.md` 一致。

## 2. 重点交付物的可执行骨架

下面的骨架都可直接照建；每一步的工具调用细节见 `graph-dsl.md`，原型细节见 `archetypes.md` 对应小节。参数写法：`model`/`modelType` 是 `configure` 顶层字段，技术参数放 `params`。

### 2.1 促销海报（带价格与机制，A2）
```
图(产品图) ──image_target──▶ 图生成「促销海报」
文(促销文案) ─text_target──▶ 图生成「促销海报」
```
- 节点：`image`「产品图」×1（`canvas_asset_import`）＋ `text`「促销文案」×1 ＋ `image`「促销海报」×1。
- 参数：`model:"gpt-image-2"`、`params:{aspect_ratio:"3:4", resolution:"1K", quality:"high"}`（照 tpl_12）。
- 文案节点正文用 `【字段】` 式三分段：`【主题】…【促销机制】…【活动时间】…`；**字段值缺就留空，不填占位数字**。
- 需要 2 个版本（横竖/双风格）→ 建 2 组「输入+文案 → 海报」，不要用 `gen_count`。

### 2.2 商品头图（带标题价格，A2）
- 节点：`image`「产品图」×1–3 ＋ `text`「头图文案」×1 ＋ `image`「头图生成」×1。
- 参数：`gpt-image-2` / `params:{aspect_ratio:"1:1", resolution:"1K", quality:"medium"}`（照 tpl_14）。
- 文案字段（tpl_14 的真实拆分）：`logo` / `logo位置` / `产品名称` / `副标题` / `卖点` / `价格` / `其他文字信息` / `主体画面内容`；建议 ≤6 个字段、每字段 ≤12 字。
- 三个头图版本 = 3 个生成节点，每个跟一套文案（tpl_14 就是 3 组）。

### 2.3 详情页成套图（A2 + A3，交付 N 张分段图）
```
图(产品图) ─┬─▶ [gpt-image-2 / 3:4 / 1K / high] 主图带卖点
            ├─▶ [gpt-image-2 / 3:4 / 1K / high] 卖点1
            ├─▶ [gpt-image-2 / 3:4 / 1K / high] 卖点2
            ├─▶ [gpt-image-2 / 3:4 / 2K / high] 精修细节
            ├─▶ [gemini-3-pro-image-preview / 3:4 / 2K] 场景图
            └─▶ [gemini-3-pro-image-preview / 3:4 / 2K] 使用场景
```
- 参数混合策略照 tpl_19：带字段落用 `gpt-image-2`（1K/2K + `high`），纯画面段落用 `gemini-3-pro-image-preview`（2K）。
- 每个生成节点的 prompt 自包含，写清"这一段要展示什么"（成分/质地/对比/使用步骤）。
- **不要承诺"自动生成一张详情页长图"**：画布只产出 N 张分段图，拼接成长图是画布之外的事（见 §3.7）。

### 2.4 多角度产品展示（A1 机位 fan-out，替代不可建的 A9）
- 节点：`image`「产品图」×1（或用户实拍的正面/侧面/背面/顶部 ×2–4）＋ `image`「角度-俯拍 / 角度-前侧45度 / 角度-后侧45度 / 角度-低机位 / 角度-广角」×3–5。
- 参数：`model:"gemini-3-pro-image-preview"`、`params:{aspect_ratio:"3:2", resolution:"2K"}`（照 tpl_65）。
- 每个节点 prompt 只写一个机位 + "保持图1产品外观、logo、材质细节一致"。
- **必须告知用户**：精确角度（水平角/垂直角/缩放）只有画布 UI 手工加多视角工具才做得到，提示词只能近似。

### 2.5 模特试衣 / 换模特（A1，参数最统一的一族）
- 节点：`image`「上传｜服饰图」＋ `image`「上传｜模特图」＋ `image`「最终输出｜全身展示」（可再加「最终输出｜杂志封面」）。
- 参数：`model:"gpt-image-2"`、`modelType:"reference_image_to_image"`、`params:{aspect_ratio:"9:16", resolution:"2K", quality:"medium"}`（tpl_116/117/119 三个模板完全一致）。
- prompt 写死分工（tpl_116 原文结构）：`图1作为模特参考，图2作为服装参考。保持图1模特的脸部特征、发型、身材比例…稳定不变，让图1中的模特真实自然地穿上图2中的服装`＋`不要随意改款，不要替换服装类别，不要额外添加无关配饰`。

### 2.6 单品拆解海报（A4）
- 节点：`image` 输入 ×3–4（产品图 + 细节图/穿搭图）→ `image`「拆解图」（`3:4` / `1K` / `high`）→ `image`「竖版海报」（`9:16` / `1K` / `high`）。
- 参数全程 `gpt-image-2` + `reference_image_to_image` + `quality:"high"`（照 tpl_89）。
- tpl_89 的 4 个输入图里有 1 张是"穿搭图"（不是产品图）——输入素材要按该模板语义配齐，不要只丢一张产品图。

### 2.7 平铺转 3D（A4 两段式）
- 第一段：`gpt-image-2` / `reference_image_to_image` / `3:4` / `1K` / `high` →「精修平铺图」。
- 第二段：`gemini-3-pro-image-preview` / `reference_image_to_image` / `3:4` / `2K` →「转3d效果」。
- 二段入边同时连"上传的原图"和"精修图"（tpl_90 就是这么连的：3 条输入边 + 3 条链式边）。
- 串行执行：精修产物回来前不能提交 3D 节点。

### 2.8 爆款复刻（图 / 视频两条路线）
- 图：参考图 + 模特图 + 替换文案 → `gpt-image-2` / `reference_image_to_image` / `3:4` / `1K` / `high` → 复刻图 + 相似风格图（tpl_86）。
- 视频：产品图 + 参考视频 → `seedance-2.5-vip-r2v` / `reference_image_to_video` / `9:16` / `480p` / `15s`（tpl_133）；参考视频由 agent 导入（缺失时再请用户补文件）。
- 88 复刻网红打卡图不可解析 → 用 86 的骨架 + "网红机位"写进 prompt。

### 2.9 九宫格分镜（A3）
- 节点：`image` 参考图 ×1–2 + `text` 剧情输入 ×1 + `text` LLM「灵感生成」×1 + `image` 九宫格 ×1。
- 参数：`model:"gemini-3.1-flash-image-preview"`、`params:{aspect_ratio:"16:9", resolution:"2K"}`（照 tpl_82）。
- T2 版（推荐，可自动跑完）：agent 直接把 9 格描述写进图节点 prompt（"3×3 宫格，每格：<内容>"），不建 LLM 节点。
- T1 版：LLM 指令要求输出 3×3 分镜 JSON（tpl_82 是全库唯一显式要求 JSON 输出的模板），**并在 plan 里标 `manualStep`**。

## 3. 电商文字与合规要点

### 3.1 带字海报优先 `gpt-image-2` + `quality`
在模板库用到的三个图模型里，`gpt-image-2` 是**唯一带 `quality` 的**（全库 42 个 `gpt-image-2` 生成节点：`high` 25 / `medium` 17）；文字类产物（头图 14、促销海报 12、卖点演示 19、拆解海报 89、外观设计图 29）全部集中在这一族。两个 gemini 图模型**没有** `quality` 字段，不要给它们塞（当前模型目录里 `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst` 也支持 `quality`，但模板库没有它们的样本，选型时以 `canvas_models` 实时返回为准）。要出字就**优先保 `quality:high`，宁可降 `resolution`**（A2 族实测 1K 占多数、high 占 7/10）。

### 3.2 文字进画面的唯一通路是文本边
`text_source→text_target`（图生成节点同时有 `image_target` 与 `text_target` 两个入口）。**结构判断式**：文案节点没有边指向生成节点，或生成节点的 prompt 里没有文字排布要求 → 产出的图里不会出现这段文案。

### 3.3 价格与促销机制必须由用户提供
促销字段（到手价、日常价、优惠幅度、活动时间、赠品）属于**事实**，缺就留空槽或改成中性创意文案；填入占位数字（如"¥99"）会被模型**画进图**，造成虚假宣传风险。字段模板照 tpl_12：`【主题】【促销机制】【活动时间】`；或照 tpl_14 的 `价格` 字段写法：`限时优惠 到手价 ￥99 日常价 ￥169 优惠 ￥70`。

### 3.4 文案不得使用绝对化用语
《广告法》第九条禁止"国家级、最高级、最佳"等用语。实操规避清单：**最、第一、顶级、极致、100%、全网最低、唯一、首个、国家级** → 改成"更…""…之一""主打…""实测数据：…"。这条落在 prompt 文本上，与画布结构无关，但**写文案节点正文时就要改掉**，不要留给用户事后改图。

### 3.5 功效宣称与资质
化妆品、食品、保健食品、医疗器械的功效/数据（如"7 天见效""祛斑""治疗"）必须由用户提供合规依据；用户没给就不写。本技能只负责视觉与结构，**不替代法务/合规审核**，交付时不要下"合规已通过"的结论。

### 3.6 logo 与商标
画面里要出现品牌 logo/商标时：让用户提供 logo 图片素材（走 `canvas_asset_import`）并书面确认有权使用，或明确接受"不出现 logo"的方案。**不要用文字描述让模型"画一个某品牌的 logo"**——模型不保证精确复刻标识，且会带来侵权风险。

### 3.7 长图与拼接
画布只产出 N 张分段图，**不提供长图拼接**：详情页长图、多格拼贴图都必须在画布之外处理（用户自行排版，或另行说明）。交付时写"已出 N 张可拼接的分段图"，不要承诺"一张长图自动生成"。

## 6. 电商场景常见错误（自查清单）

1. 从**输入图节点**读 `model/quality` 当配置用 → 那是残留，配置只写在生成节点上。
2. 给 `gemini-3-pro-image-preview` / `gemini-3.1-flash-image-preview` 写 `quality` → 模板库三个图模型里只有 `gpt-image-2` 有。
3. 用 `gen_count:4` 出套图 → 模板库的做法是 4 个节点。
4. 拿 **84/85/70/71/87/88/42/98** 这类只有名称的模板当结构证据 → 只能当存在性证据，要换成同族可解析模板。
5. 海报文案里填占位价格（"¥99"）→ 会被画进图，构成虚假宣传。
6. 文案节点没有连 `text_target` 边（或生成节点 prompt 里没有文字内容）→ 图里不会出现文案，别按"带字海报"交付。
7. 使用绝对化用语（最/第一/100%/国家级）。
8. 承诺"自动生成详情页长图 / 自动拼接"——画布不提供长图拼接。
9. 默认上 `4K` / `1080P` → 电商交付 `1K`/`2K`/`480p` 足够，成本差在计费点上（`gpt-image-2` 13–895、`gemini-3-pro-image-preview` 95–164、`seedance-2.5-vip-r2v` 336–13500）。
10. 一次提交多个生成节点 → 串行执行，且 `canvas_run` 要求上游已有产物。
