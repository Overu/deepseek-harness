# 活动案例检索

调用 RAGFlow `/api/v1/retrieval` 接口，把返回的**活动档案 JSON** 渲染成人类可读报告，并**按固定格式交付**。
在线检索必须通过企业插件的统一 API 网关 `activity-search` 连接发送；企业插件携带当前登录态，后台管理 RAGFlow 地址与凭据。技能不得读取、索取、展示或写入任何 RAGFlow Token，也不得直连 RAGFlow 服务。

## 🚨 第一原则：不要输出原始响应

接口返回的是**嵌套 JSON 字符串**（HTTP 响应一层包装 + `chunk.content` 里又是一层 8000+ 字符的 JSON 文本），
直接展示给用户完全不可读。**必须用本技能的脚本渲染后再输出。**

- ❌ 不要把 `curl` / 原始 JSON / `chunks`、`doc_aggs`、`content_ltks` 等字段名贴给用户
- ❌ 不要给 `chunk_id` / `document_id` / `dataset_id` 等内部标识
- ✅ 用脚本输出结构化报告；需要细节时告诉用户可以加 `--full`

## 快速使用

```bash
python3 scripts/ragflow_retrieval.py "巧克力"                    # 默认 = 事件式报告
python3 scripts/ragflow_retrieval.py "巧克力" --full             # 展开装置细节/玩法流程/逐张图片文案
python3 scripts/ragflow_retrieval.py "巧克力" --page-size 20 --threshold 0.5
python3 scripts/ragflow_retrieval.py "巧克力" --style compact    # 一行一条速览（先看命中概貌）
python3 scripts/ragflow_retrieval.py "巧克力" --mentions 0       # 不拆分附录，全部当主体
```

脚本路径相对于本技能目录。默认只依赖 Python 3 标准库，无需安装任何依赖。

### 输出风格

| `--style` | 用途 |
|---|---|
| `report`（默认） | **事件式报告**：概览表 + 逐场卡片（含原帖链接）+ 附录 + 使用提醒 |
| `compact` | 一行一条：序号、相似度、活动名、时间、品牌 —— 用于快速筛选 |
| `plain` | 同 `report` 但去掉 Markdown 标记，适合纯文本渠道 |
| `markdown` | 旧版逐命中文档式报告（保留兼容，不再作为默认） |
| `formatted` | 缩进版关键字段视图，需要看字段结构时用 |

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--page-size` | 5 | 返回条数（`total` 是命中总数，脚本会分别展示） |
| `--threshold` | 0.6 | 相似度阈值，**没结果时优先降这个** |
| `--weight` | 0.75 | 向量相似度权重，其余给关键词 |
| `--mentions` | 1 | 相关性门槛：关键词在「名称/品牌/行业/标的」中出现次数少于该值 → 放入附录；`0` 关闭拆分 |
| `--full` | 关 | 展开装置全部视觉特征、玩法参与流程、逐张图片画面与文案 |
| `--timeout` | 60 | 超时秒数 |
| `--json-out PATH` | — | 可选：原始响应落盘（给下游程序用，**不要展示**） |
| `--save-md PATH` | — | 可选：渲染结果另存文件 |
| `--raw-file PATH` | — | 离线渲染已保存的响应，不发请求 |

## 📐 输出规范（`report` 格式，后续一律按此交付）

脚本已经生成下列骨架，**Agent 不要重排结构、不要删段**；只在其上做三件事：补「可复用点」、
补「一句话结论」、必要时补覆盖盲区说明。

### 固定结构

```
# 检索结果：<query>
命中 N 条切片｜归并为 M 场活动（K 篇笔记）｜total=…｜耗时
> 归并说明 + 判断类型提示

## 概览
| # | 活动 | 时间 | 地点 | 品牌 | 笔记 |

## 逐场详情
### 1. <活动名>
- 时间 / 地点 / 品牌·行业 / 场地 / 活动目标
- 📎 原帖：<笔记A>；<笔记B>        ← 必带，可点击
**活动标的** …
**目标群体** …
**装置与布景** …
**空间分区** …（含参观动线）
**互动玩法** …（门槛 / 奖励 / 完成条件；--full 才有流程）
**笔记图片**：N 张
🆕 **可复用点**：1–2 句（仅提炼档案事实，不编造）

## 附：仅被提及（不作为活动主体）
- 活动名（品牌）：提及 N 次｜语境「…」｜原帖

## 使用提醒
- 判断类型 / 时间缺失 / 相关性分层 / 链接时效 / --full 提示
```

### 硬性规则

1. **链接必须给**。每个活动输出 `原始链接`（小红书 `discovery/item/<note_id>`），
   同活动多篇笔记并列；链接含 `xsec_token` 会过期，提醒可按笔记 ID 搜索。
2. **归并同名活动**。同名 + 同档期 + 同城市视为一场，主档案取信息量最大的一份，
   其余标「已归并 K 篇笔记」。**同名但档期/地点不同不要合并**（如圣诞场与 520 场）。
3. **保留判断类型**。`确定事实` / `合理推断` 原样标注，推断不得写成结论。
4. **时间缺失要显式写**「档案未标注」，禁止用活动名或图片日期臆测档期；确需推断时写明依据。
5. **相关性分层**。关键词只出现在图片文案/道具/风味描述里的，进附录并给一句语境，
   不要混进主体活动，也不要在正文里当案例引用。
6. **每场一个「可复用点」**。只基于档案事实（结构、动线、门槛、奖品设计）提炼，1–2 句；
   没有可提炼的就写「无」。
7. **结尾一句话结论**。说明这批案例能支撑什么判断、缺什么（覆盖盲区），并给出下一步检索建议
   （换品牌名/品类词/玩法词，或补数据）。
8. **不重复、不注水**。同一活动只出现一次；概览表与详情不得互相复述大段内容。

### 什么时候不用默认格式

- 用户只要「有没有 / 有几场」→ `--style compact`，再补一两句判断，不必展开卡片。
- 用户要排查接口/数据问题 → `--style formatted`，可展示字段结构（仍不给内部 ID）。
- 用户明确要「原始数据/JSON」→ 用 `--json-out` 落盘给路径，不在对话里贴内容。

## 配置

- 企业连接：`activity-search`，固定只允许 `POST /api/v1/retrieval`。
- 后台配置：`RAGFLOW_BASE_URL`、`RAGFLOW_API_KEY`；不得下发到技能包、客户端环境或命令行。
- 默认知识库：内置活动档案 dataset；如确需覆盖，可在客户端环境设置 `RAGFLOW_DATASET_IDS`，多 dataset 用逗号分隔。
- 运行前提：企业插件已安装并启动，用户已登录，运行环境包含 `DSH_HOME` 与 `DSH_SKILL_PROXY_NODE`。
- 代理不可用、超时或结果不确定时停止请求，不自动重试，也不改为直连。

## 使用流程

1. 关键词直接检索；长句需求先抽 2–4 个核心词分别检索，再合并去重。
2. 先 `--style compact` 看命中概貌，判断相关性；命中里常有字面噪声（见踩坑清单）。
3. 用默认 `report` 出正式结果；确认命中后再决定是否 `--full` 展开。
4. 交付时按「输出规范」补可复用点、一句话结论、使用提醒。

## 返回数据说明

知识库是**结构化活动档案库**，每个切片是一份或数份活动档案，字段为
`原始链接 / 平台 / 活动名称 / 活动时间 / 地理位置 / 场地属性 / 品牌 / 行业 / 活动标的 / 活动目标 / 目标群体 / 布景搭建 / 空间分区 / 互动玩法 / 活动图片`。

`原始链接` 与 `平台` 是溯源字段，**必须展示**；其余字段的 `判断类型`（`确定事实` / `合理推断`）表示该值是原文明确写出还是模型推断。

字段细节、响应形态差异、错误码见 [references/api-notes.md](references/api-notes.md)。

## 踩坑清单

- **`chunk.content` 是字符串不是对象**，且形态有三种：单份档案 dict、多份档案 list、纯文本。
  脚本已统一处理，不要自己写 `json.loads` 后直接取 `["活动名称"]`。
- **可能存在 ```json 代码围栏**，解析前必须剥离。
- **响应有两种包装**：`{code:0, data:{...}}` 与裸 `{chunks,...}`。脚本兼容两者；
  业务成功要判 `code == 0`，不能只看 HTTP 200。
- **`total` 会出现两次**，不要重复展示。
- **命中数少 ≠ 接口故障**，多数是该 dataset 确实没有素材；先确认入库情况再调阈值。
- **相似度不可当相关性**：`巧克力` 查询会召回威士忌、护肤、潮玩（关键词只出现在图片文案里）。
  这类一律进附录，并在回答里说明"相关性存疑"。
- **别把「风味/配色」当品类活动**：如"薄荷巧克力口味冰淇淋""黑巧克力柑橘气息"，
  只是产品口味描述，不是巧克力品牌线下活动。
- **`原始链接` 可能是字符串也可能是数组**，脚本已兼容；不要假设它一定存在。
