# AARRR 用户行为与增长

**作用与对象**：用获客、激活、留存、推荐和变现检查产品增长链路。适合行为诊断和指标设计；不是内容热度或品牌认知的替代测量。

**输入与粒度**：按当前问题定义产品、期间、事件与计量单位。获客量、收入结构等可使用口径明确的聚合资料，无需先取得用户级标识；测留存或跨阶段转化时，再检查相应人群/队列匹配、事件资格、去重、分母和缺失。没有足够行为依据时可设计测量和成因假设，不补造真实漏斗率。

**操作**：
- Acquisition：相关用户如何到达，渠道和计量单位是什么。
- Activation：用户首次获得核心价值的行为是什么；注册不自动等于激活。
- Retention：在适合产品频率的窗口内，哪些符合资格的用户继续使用或选择。
- Referral：实际推荐、邀请或带来他人的行为；点赞不等于推荐转化。
- Revenue：购买、续费或其他适用变现，区分订单、人数、收入、利润与退款。

按问题选择渠道、版本或适用队列等比较维度，需要解释差异时再提出竞争性解释和验证。业务可先发生推荐再付费，也可多次返回后购买，观察顺序按问题调整。

**可交付**：事件与指标定义、局部行为诊断、证据缺口和研究/实验问题。

**边界与缺口**：不把不同分母、月份或非连续人群拼成转化路径；不从两个订单总数算用户留存或归因。此框架原始排列见McClure资料，后续常见版本交换推荐与变现，说明口径即可，不强制全业务线性执行。

**衔接**：4C/5A帮助提出障碍解释，PMF检查契合假设，差距分析组织测量和改善。见[来源校准](../source-calibration.md)。
