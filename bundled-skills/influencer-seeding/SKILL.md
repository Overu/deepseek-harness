## 企业版数据调用

TikHub 只读请求通过本目录 `scripts/tikhub_readonly.py` 和 `scripts/enterprise_proxy.mjs` 访问统一 API 网关的 `tikhub` 连接。企业插件携带当前登录态，后台管理供应商凭据与请求头。技能不读取本地厂商 Key，不直连供应商接口。合同状态、参数校验、研究预算预留和响应净化保持在技能中执行；网关失败或结果不确定时停止请求，保留费用预留，不自动重试。

# 达人种草营销 · 全案技能

**定位**：单/少平台达人**种草**全案（以内容种草＋投流放大为主线；多平台整合走 `influencer-integration`）。

**适用**：达人种草全案、KOC/KOL 种草地铺、投流放大策略、种草效果预估。
**不适用**：**多平台**达人整合营销 → 用 `influencer-integration`；**含线下渠道**的全渠道整合、品牌战略定位 → 用 `soccor-proposal`；**线下执行细节**（排期/物料/场地）超出本技能范围，需另开专门任务。

**触发词**：达人种草方案 / 种草全案 / KOC 种草 / 种草策略 / 投流方案 / 小红书种草 / 抖音种草 / 爆文打造。

## 0. 通用纪律（先读；完整版见 references/dsh-rules.md）

- **默认直出内容**：直接输出在对话里——不落盘、不推送、不生成文件，**不要**问"要不要 HTML / PPT / 推送到 IM"。用户明确要求文件时写 `<workspace>/output/` 并用 `present` 交付，要求推送时用 `de_channel_send`。
- **偏离必须显式声明**：规则与环境或用户指令冲突时，当场说明取了哪条、弃了哪条；优先级 `用户当轮指令 > 本节 > 其余章节 > 历史案例经验`。
- **不编造数据**：一切数字要么有可点击来源，要么标注「推算值 + 计算口径」。
- **合规红线**：禁绝对化用语（最/第一/唯一/100% 等）、商业内容须标"广告"、医疗医美保健食品金融教育各有硬限制、素材与肖像须授权；交付前逐项自查。
- **交付物纯净度**：交付物只写结论、方案、数据与来源——**不得出现过程叙述、推理与权衡、内部编号（§x.y/MKT-xxx）、元评论（「值得注意的是」）、自我确认（「已自检通过」）或寒暄**。写完逐句问：这句是给用户的信息，还是我自己的过程？

> 📖 四条规则的完整表述、行业限制细则与交付前检查清单：见 [`references/dsh-rules.md`](references/dsh-rules.md)。**按需读取**。

**输出兼容约束**：本版本保留原技能的最终板块、两段式确认、观点/篇幅、引用和交付规范；详见 [`references/output-contract.md`](references/output-contract.md)。新增证据、接口与计算结构只用于内部校验，不额外输出技术章节。

## 2. 执行流程（阶段 0–8）

```
阶段 0  直接开写（默认对话内输出，第 0 节交付默认）
阶段 1  Brief 收集
阶段 2  数据检索（必选，§4）
阶段 3  分析输出（平台趋势 / 竞品 / 本品 / 人群）
阶段 4  种草策略（传播主题）  →  ⏸️ 唯一强制确认节点
阶段 5  媒介策略（达人矩阵 + 投流策略）
阶段 6  种草规划（Roadmap）
阶段 7  效果预估（预算 / 分层 KPI / 优化决策点）
阶段 8  交付（默认对话内直出）
```

### 阶段 1：Brief 收集

需要 5 要素：① 品牌/产品 ② 目标平台 ③ 预算范围 ④ 周期/节点 ⑤ 核心 KPI（曝光/互动/转化/搜索）。

可从上下文补充产品价格/规格、可证实卖点、销售承接、历史投放数据、预算含费范围和可用后台权限；仅对会改变方案的关键缺口提示，不把扩展字段变成新的强制问卷。

**缺失项的处理**：列出假设值继续推进，**不要把提问变成阻塞**。在方案开头单列「待确认事项」，标注哪些数字是基于假设测算的（遵守 第 0 节数据规则）。

### 阶段 4：种草策略 / 传播主题 —— 唯一强制确认节点

- 生成 **3–5 个**传播主题（含话题词、Message House、种草方向），每个须完成人性需求连接。
- 输出后**立即停止**，标注 `⏸️ 等待确认`，说明「确认后将继续输出媒介策略、种草规划、效果预估」。
- 不要附上达人矩阵、投流预算等下游内容。

**例外**：用户在 Brief 阶段就明确说「直接给完整全案」→ 跳过本节点，一次性输出。

## 3. 输出节奏（本技能只有一种默认节奏）

**默认：两段式**

| 段 | 内容 | 结束方式 |
|----|------|----------|

- ❌ 在用户确认前输出达人矩阵 / 投流预算等下游内容；
- ❌ 把第二段再切成多次让用户反复说「继续」；
- ❌ 跳过确认节点（除非用户主动要求）。

> 说明：早期版本同时存在「必须等确认」与「必须一次性输出完整方案、禁止分多次」两条互斥规则，本节是唯一裁定。

## 4. 检索与引用规范

**5 大检索方向（必选环节）**：阶段 2 先读 [`references/data-sourcing.md`](references/data-sourcing.md)，按问题选择 DSH 联网与 TikHub，并维护内部证据账本；没有 TikHub 时仍完成 DSH 检索，不省略板块。

| 方向 | 目的 | 来源 | 输出要求 |
|------|------|------|----------|
| 竞品分析 | 定位、产品与可见种草策略 | DSH 搜索官方资料/案例；TikHub 补公开内容、作者与评论 | ≥3 个竞品，含达人类型/内容方向/实际可得互动及原链接；样本不可当全量投放 |
| 行业报告 | 市场规模/趋势/偏好 | DSH 搜索统计机构、研究发布方、平台原始报告 | 优先最新且匹配品类与数据期的资料，标注发布方、发布时间与统计期 |
| 平台热点 | 话题热度/搜索趋势 | DSH 官方热点/报告；实测有效的 TikHub 指数、榜单、扩词 | 当前窗口、指标定义与样本范围；指数不可替代市场规模 |
| KOL 报价 | 验证预算可行性 | 当前有效的商业字段、品牌/MCN 询价、DSH 可核验公开报价 | 各层级参考范围及合作形态/含费范围/有效期；缺数据列假设或待询价 |
| 案例参考 | 可借鉴机制与执行 | DSH 原案例/品牌资料、数英/SocialBeta/广告门、可用灵感库 | ≥2 个，含创意概念与执行细节；未核验历史案例不能冒充已检索证据 |

**引用格式**（缺链接视为不达标）：

```markdown
**数据来源：**
1. [文章标题](URL) — 发布机构，发布日期
```

**铁律**：必须检索最新可获得且口径适用的数据，禁止仅凭知识库估算市场规模与增长率；每个数据点标注来源与时效；核心数据（市场规模/竞品销量/价格）不得估算，无公开数据就写「暂无公开数据」。
**禁止**：编造数据/链接；引用无来源的二手转述；用"约""大概"代替检索。

## 5. 分析规范

**必备板块**：Brief 解读 · 平台趋势分析 · 竞品分析 · 本品分析 · 人群分析。

**观点提炼铁律**：重点不是信息搜集而是信息分析 —— 每部分收敛出 **1–2 个核心观点**，每个观点 **≤3 个支持点**，支持点须有来源佐证。

**竞品分析框架**：分析 **3–4 个**核心竞品，每个含品牌/产品定位、核心消费群、核心卖点、种草内容方向、投放达人矩阵与量级、不足与优势，并附具体账号/笔记链接。

## 7. 种草策略与创意规范

### 7.1 传播主题生成规范

**核心原则**：传播主题必须与人性需求形成逻辑闭环。

| 品牌 | 传播主题 | 人性需求 | 创意手法（标准分类） |
|------|----------|----------|---------------------|
| 王老吉 | "吉来运转" | 情感需求 - 亲人陪伴 | 消费者投射（生活片段、价值认同） |
| 风神汽车 | "不信极限" | 尊重需求 - 被认同 | 电影型（成长与逆袭） |
| 小鹅拼拼 | "小拼一下，就很开心" | 情感需求 - 友人相聚、组织 | 幽默/有趣（拟人）＋艺术化（IP 形象） |
| 维意定制 | "所梦，即所得" | 审美需求 - 时尚美；自我实现 - 个性 | 艺术化（意象化）＋电影型（圆梦） |

### 10.1 达人矩阵配置

原有新品牌/成长/成熟阶段的头腰尾配置及 7:25:68 只作为历史构型参考，不是必须执行的预算比例。先看场景、可比内容、报价与交付条件，再确定矩阵；明确比例是人数、内容数还是费用。人数取整数、预算闭合，未知报价标假设/待询价。

真实名单必须有账号链接与数据时点；受众、完播、阅读、成交缺失时保留缺口，不由昵称、粉丝、互动反推。各层级报价范围须按本次 DSH 检索、有效 TikHub 商业字段或客户询价校准。

### 10.2 投流效果评估

按 [`references/platform-benchmarks.md`](references/platform-benchmarks.md) 的同口径指标与样本基线评估；广告产品/目标/周期不同不混用阈值。列出首测、观察、调整和停止条件，样本不足时不强行判断。平台商业合作、内容加热与广告购买分别说明；没有第一方投流数据时只给明确的情景预测。

### 10.3 种草规划节奏

| 版本 | 阶段划分 | 时长 | 预算分配 | 适用 |
|------|----------|------|----------|------|
| 标准版（历史节奏参考） | 预热期 / 引爆期 / 延续期 | 6–8 周 | 20 : 60 : 20 | 全案投放 |
| 快节奏版（历史节奏参考） | 预热&官宣 / 心智夯实 / 持续种草 | 2–3 周 | 38 : 5.5 : 56（旧例合计 99.5，实际分配需归一） | 明星代言＋事件营销 |

|------|----------|

### 10.4 分层 KPI

保留过程指标、结果指标和有数据支持的 5A 人群资产；逐项标明来源/权限、指标口径、观察与归因窗口。**ROI 口径必须写清**：最后一跳可能不能完整解释种草影响，但不能以此宣称低 ROI 正常或自动补计未观测销售。公式与成本范围统一见 [`references/platform-benchmarks.md`](references/platform-benchmarks.md)。

## 12. 禁止行为总表

| 违规行为 | 说明 | 等级 |
|----------|------|------|
| ❌ 未经用户要求创建文件 | 违反 第 0 节交付默认（默认直出） | 🔴 严重 |
| ❌ 编造数据/引用 | 所有数据须真实可查 | 🔴 严重 |
| ❌ 无引用来源 | 每个数据点必须标注来源 | 🔴 严重 |
| ❌ 跳过确认节点 | 传播主题须等用户确认（除非用户主动要求跳过） | 🔴 严重 |
| ❌ 静默偏离技能 | 偏离/冲突不声明 | 🔴 严重 |
| ❌ 用知识库估算市场规模/增长率 | 必须检索；无数据写"暂无公开数据" | 🟠 中 |
| ❌ 分多次输出让用户说"继续" | 确认后应一次给完 | 🟠 中 |
| ❌ 省略核心板块 | 检索增强/竞品分析/效果预估不可省 | 🟠 中 |

| ❌ 种草内容无人性需求连接标注 | 必须标注标准分类 | 🟠 中 |

## 13. 输出前检查清单

**交付与偏离**
- [ ] 是否只在对话内输出、未擅自创建文件？（第 0 节交付默认）
- [ ] 若有偏离，是否已显式声明？（第 0 节偏离规则）

**检索与数据**
- [ ] 是否完成 5 大方向检索？DSH 客户端联网不可用时是否按问题降级并告知用户？TikHub 是否仅使用有效字段？
- [ ] 每个数据点是否标注来源并可点击复核？核心数据是否避免了估算？
- [ ] 假设值是否明确标注为推算？

**分析**
- [ ] 是否覆盖 Brief 解读 / 平台趋势 / 竞品 / 本品 / 人群？竞品 ≥3 个？
- [ ] 每部分是否收敛出 1–2 个核心观点、每个 ≤3 个支持点？

**人群与创意**
- [ ] 人性需求是否取自 7 大分类 224 项标准名称？
- [ ] 创意手法是否取自 3 大类 98 项标准分类？
- [ ] 是否生成 3–5 个候选传播主题并按原两段式标注 `⏸️ 等待确认`？用户明确要求完整全案时按原例外跳过等待。
- [ ] 种草内容是否有人性需求连接标注？篇幅是否符合 §7.5 标准？

**策略与交付**
- [ ] 达人矩阵、投流预算分配、Roadmap、分层 KPI 是否齐备？
- [ ] 是否给出投中优化决策点（关停/优化阈值）？
- [ ] ROI 口径是否写清局限性？
- [ ] 预算是否闭合，人数是否取整，费用是否重复，指标分母/统计期是否一致？自然与付费、毛展示与去重人数是否分开？
- [ ] 未知数据是否保留缺口，接口历史状态是否与本次健康检查分开，内部技术字段是否未泄露到交付正文？
- [ ] **交付物纯净度**：只含结论/方案/数据与来源，无过程叙述、推理、内部编号、元评论与自我确认？
