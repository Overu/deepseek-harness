# DSH 联网检索与 TikHub 取证

在阶段 2 读取本文件。取证服务于原有输出板块，不改变确认节点、交付格式与禁止编造规则。

## 来源分工

| 问题 | 优先来源 | 补充与边界 |
|---|---|---|
| 市场规模、行业趋势、政策、品牌/产品事实 | DSH 客户端当前提供的联网搜索与网页读取能力，通常为 `web_search` / `web_fetch` | 优先统计机构、平台、品牌及研究发布方原文；TikHub 搜索结果量不能替代市场规模 |
| 竞品定位、上市、价格与产品依据 | DSH 联网搜索、品牌官网、官方店铺和报告原文 | 价格保留规格、促销条件与日期；未公开的销量/预算不估算 |
| 竞品种草内容、账号、互动和讨论 | TikHub 搜索→相关性过滤→详情→评论；DSH 检索补充账号/笔记与官方案例 | 品牌提及不等于付费合作；样本不等于竞品全量投放 |
| 平台趋势与热点 | DSH 检索平台最新报告、官方热点；可用的 TikHub 指数/榜单 | 指数、排名、绝对人数分别记录；搜索联想不等于搜索量 |
| 达人报价与商业表现 | 实测有效的星图字段；客户/MCN 当期询价；DSH 查可核验公开报价 | 挂牌价、估算价、合同价分开；不可用时仅给明确的预算假设或待询价 |
| 创意案例 | DSH 检索原案例、品牌官方材料；可用的 inspiration-api | 至少 2 个可核验案例；案例描述与本次效果预测分开 |
| 产品功效与主张 | 品牌提供的产品文件、检测材料、官网可复核证据 | 评论与达人体验不能替代产品功效证据 |
| 真实投流成本、A3、点击、成交与 ROI | 客户授权的广告/电商/归因后台或导出数据 | TikHub 有对应字段也先核验来源、权限、定义和周期；公开互动不可反推 |

不要假定 DSH 的工具名称或 API Key 要求永久固定：先使用本次环境实际暴露的客户端联网工具，不能因为没有独立搜索 Key 就跳过客户端搜索。没有网页读取工具时保留原链接、可见摘要与未核验状态，不能把摘要当已读全文。不可用时用客户端其他已配置搜索/读取能力与已知官方页面；案例库仅补案例，不能代替市场或报价证据。每个查询族最多两次有针对性的改写/替代；仍无数据就说明缺口，不无限重试。

## 查询与抽样

1. 记录品牌、产品、竞品别名、品类词、场景/问题词及排除词。按研究问题分别检索，不只搜品牌名。
2. 市场报告记录发布日期和数据覆盖期；优先当前可获得的最新且匹配口径的资料，不再用“2023 年后”作为新鲜度判定。
3. 内容搜索记录平台、时间过滤、排序、分页/会话、查询时间、去重后数量。按内容 ID 去重；跨查询命中同一篇不累加。
4. 不只选热榜爆款。尽量同时覆盖近期排序、综合排序及不同表现内容；热度抽样用于找机制，不能据此估计平均水平。
5. 详情核对对象、正文、发布时间与品类相关性；商业标识记 confirmed / suspected / unknown，标题出现品牌不自动标 confirmed。
6. 评论保留抽样方式、实际返回量、关联内容及反例；热门评论不是随机样本。结论写“在本次可见样本中”，不泛化全体消费者。
7. 内容与账号链接使用原始平台可复核链接；不要把 TikHub 临时缓存链接或带凭证链接写进方案。

## 内部证据账本

在上下文中维护以下结构；默认不落盘、不在最终方案展示技术字段。

```json
{
  "evidence_id": "E001",
  "source_type": "public_observed",
  "platform": "xiaohongshu",
  "provider": "tikhub",
  "source_title": "实际返回的笔记标题",
  "source_url": null,
  "entity_id": null,
  "retrieved_at": null,
  "published_at": null,
  "endpoint": null,
  "request_id": null,
  "field_path": null,
  "metric": null,
  "value": null,
  "unit": null,
  "denominator": null,
  "metric_window": null,
  "query_context": {},
  "sample_size": null,
  "limitations": []
}
```

`source_type`：`public_observed`（公开观察）、`platform_estimated`（平台估算）、`first_party_actual`（授权实际）、`derived`（计算结果）、`hypothesis`（规划假设）。DSH 获取的报告也使用同一账本，只把 provider 改为客户端检索通道，并记录发布方。派生结果必须列输入证据 ID 与公式；策略判断保留支持/反对证据；规划假设不能升级为已核验事实。

HTTP 成功、接口文档和模型解释分别只能证明传输、能力说明和分析，不能替代业务证据。缺失与真实零值分开；来源不足时不得把猜测填成 0。客户私有资料标明提供方、日期和口径，不上传换取链接。

## TikHub 接入

只用企业插件已配置的统一 API 网关 `tikhub` 连接，其调用遵守 [接口合同](tikhub-endpoints.json)。运行 `scripts/tikhub_readonly.py` 从标准输入接收请求，默认 dry-run；后台管理凭据与鉴权。脚本不读取本地厂商密钥、配置或 Cookie，不执行下单、加热、私信、邀约、支付。连接不可用时继续客户端联网检索并记录数据缺口。

真实调用前确定平台、查询范围和本次剩余研究费用上限；已有授权与预算沿用，不重复征求。缺少付费取数所需权限/预算时，继续 DSH 免费/已授权检索并交付有边界的结果，不能阻塞整个方案。请求价格必须来自当前端点/账户计价，不能沿用旧合同每次统一 0.002 美元。具体使用见 [脚本合同](script-contract.md)。

接口状态区分 `historically_verified`（历史快照）、`current_status`（最近一次健康检查结论：`live`/`failed`/`catalog`）、`catalog`、`failed`；两者冲突时以 `current_status` 与 `revalidated_at` 为准。先对一个相关对象进行业务健康检查，再扩样；画像等对象接口还需两个不同对象匹配检查，防止固定默认响应。校验 HTTP、业务码、嵌套状态、对象 ID、时间窗、字段语义和相关性。脚本仅作传输和基础载荷检查，返回 `needs_semantic_validation` 不能直接用于正式评分。2026-10-16 复测：`xingtu_search_creator` 已 failed（发现改用 `xingtu_search_kol_v2`）；`xingtu_author_market_fields` 两个不同达人返回同一份选项字典（静态枚举，非达人画像），不得当成达人级富集；`douyin_hot_total_list` 需 `type=range` 加起止日期，snapshot 模式须传有效 `snapshot_time`。

目前登记失败的星图受众画像默认不使用；恢复需单独探测。小红书 PGY 为文档候选能力，不默认承诺受众/报价/阅读可取得。脚本未开放的能力通过已配置连接器和已验证合同获取；不能临时拼接未知路由绕开校验。
