# 达人种草技能的 DSH 交付与合规规范

> 本文件为本包的 DSH 交付与合规规范；来源于原包共享规则，本版本已按本技能维护。数据路由以 [data-sourcing.md](data-sourcing.md) 为唯一入口。

## 交付默认（默认直出内容）

本技能默认把完整内容**直接输出在对话里**：不落盘、不推送、不生成文件。**不要**在开头或结尾询问用户"要不要 HTML / PPT / 推送到 IM"——用户需要这些形式时会自己明确说。

- **用户明确要求文件**（HTML / PPT / 文档等）：按当轮要求生成，写入 `<workspace>/output/`，用 `present` 交付。
- **用户明确要求推送到渠道**（飞书 / 企微 / 微信等）：用 `de_channel_send` 发送。
- **用户未明确要求**：只在对话内输出，不创建任何文件。
- 用户当轮指令优先，无需为改变交付方式另行征求同意。

**为什么有这条**：方案文件属于「用户有感知」的产物，未被要求就落盘会让用户在自己的工作区发现非预期文件；反过来，每次追问交付形式同样是噪音。

## 偏离必须显式声明

本技能的规则是经验默认值，不是用户的指令。遇到下列情况必须**当场说明**，不得静默处理：

- 某条规则在本环境不适用（例：某条依赖外部上传服务的要求在本环境无法满足）；
- 两条规则互相冲突 → 按 `用户当轮指令 > 第 0 节 > 其余章节 > 历史案例经验` 取舍，并说明取了哪条、弃了哪条；
- 为满足用户指令而偏离本技能（例：用户要求改用指定交付形式）。

## 不编造数据

市场规模、竞品销量、报价、CPA3/CPE/爆文率等一切数字：要么来自检索并附可点击来源，要么明确标注为「推算值 / 假设值」并写出计算口径。**禁止把估算值写成事实**。

## 检索降级通道（web_search 不可用时）

不得因单一工具不可用跳过全部检索。先检查 DSH 客户端本轮已配置能力，再按 [data-sourcing.md](data-sourcing.md) 使用同用途的搜索、原始官方页面、用户提供材料或有效接口。案例库只能补创意案例，不能补造市场规模、销量或报价。

实际使用替代通道时按原偏离规则简要说明，并提供可复核原文入口；不要叙述内部调用过程或暴露技术日志。

## 合规红线（输出前必检）

对文案、创意、达人 Brief、投放方案与物料先内部自查、命中问题先改后交。最终只呈现影响执行的限制和需核验事项，不输出“自检通过”或技术清单。

- **绝对化与事实主张**：保持原技能的保守文案标准，避免未经证明的最高级、唯一、100% 等。区分品牌禁用语与法定禁止，不将所有含“最”的表达或“无添加”等一概解释为同一法条禁词。功能、效果、成分与比较主张应有适用证据。
- **广告可识别性**：商业内容不得隐匿商业属性；结合合作形态、购物链接和当前平台规范落实显著标识。需要依法标注“广告”的情形不得用模糊标签替代；没有核验发布状态时不得宣称已经标注。
- **行业准入**：先核验品类是否允许广告、该合作是否构成代言、是否需事前广告审查。医疗、药品、医疗器械、保健食品等的代言限制不能仅用“禁止疗效承诺”替代；教育、金融、酒类、烟草等按实际品类、地域、形式与平台规则核验。禁止的形式不生成执行建议；不确定处提示待核，其他分析继续。
- **未成年人**：区分代言、形象使用和消费引导；不得使用不满十周岁未成年人作广告代言人，其他年龄、品类及平台约束按实际核验。品牌更严格的形象禁用规则优先遵循，不冒称为普遍法律规定。
- **数字与授权**：数字有来源或明确推算；素材、肖像、商标、二创和付费投流等使用范围分别核验。没有授权证据时写待核，不写“已授权”。

按项目通过 DSH 客户端联网复核当前规则；维护参考：[广告绝对化用语执法指南](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/ggjgs/art/2023/art_64279265c896452f8f638f2de12b8003.html)、[广告代言指导意见](https://www.samr.gov.cn/ggjgs/tzgg/art/2023/art_79fe72737f6d435591abc9eafca30e88.html)、[互联网广告管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html)。

## 交付物书写规范（输出纯净度）

本技能的规范同时包含「给执行者的规则」与「给用户的交付物」两类内容。**交付物只允许包含后者**：规则、清单、编号、变更记录是执行者用的，写给用户看的东西里不出现。

**交付物中必须删除**（出现即视为不合格）：

- **过程叙述**：先做什么、后做什么、经过几轮、检索了哪些关键词、调用了什么工具；
- **推理与权衡**：为什么选 A 不选 B、考虑过哪些可能、判断依据是怎么推导出来的；
- **对技能自身的引用**：`§0.3`、「按技能要求」、「根据规范」、`MKT-013` 之类的内部编号与章节号；
- **元评论与过渡语**：「值得注意的是」「需要说明的是」「综上所述」「接下来我们看」；
- **自我确认**：「已按模板输出」「已逐项自检通过」「符合规范要求」；
- **复述需求或技能背景**：把 Brief 原文、技能适用场景、方法论来源再抄一遍当作开篇；
- **寒暄与情绪**：「希望对你有帮助」「如有需要请随时告知」「希望这份方案能帮到你」。

**交付物中允许保留**：结论、方案、数据与事实；数据来源与引用；规范要求时的置信度、风险与限制说明；第 0 节要求的偏离声明（它本就是写给用户看的）；用户明确要求补充的说明。

**判定方法**：每写完一段，逐句自问「这句是给用户的信息，还是我自己的过程？」——是过程就删。如果删掉之后方案不再成立，说明它本应**改写成结论句**：

- ❌ `我检索了三个平台，发现 CPM 普遍偏高` → ✅ `三个平台 CPM 均高于 35 元基准（来源：…）`
- ❌ `根据 §7.2 的要求，我选择电影型手法` → ✅ `创意手法：电影型（情感叙事）`
- ❌ `下面我按 Brief 解读、人群分析、策略的顺序展开` → ✅ 直接写各节标题

**适用范围**：对话内输出与文件 / HTML / PPT / 文档交付物一视同仁，标准不因形式放宽。文件产物中尤其禁止出现「分析过程」「思路说明」「技能规范摘要」「变更记录」等章节。本包合规自查为内部过程；用户明确要求清单时才展示。

## 交付物规范

默认：完整内容直接在对话内输出，不落盘。用户明确要求文件或渠道推送时，按本节下面两小节执行。

### 默认：对话内输出（不落盘）

- 完整方案直接在对话中输出，**不落盘**。
- 按各技能自己的输出节奏章节（两段式 / 一次给完）执行；确需分段时每段开头标注进度（如「1/2 策略篇」）。
- 用 Markdown 表格与 `dsh-ui` 结构化组件承载数据，比纯文本更好扫读。

### 用户明确要求文件时（HTML / PPT / 文档）

- 路径：`<workspace>/output/<项目名>_<技能名>.<扩展名>`（HTML 用 `.html`，PPT 用 `.pptx`）。
- 单次写入控制在 10KB 以内：先写骨架＋CSS，再用占位符逐章追加。
- 全篇共用一套 CSS；每章留导航锚点；移动端与打印可读。
- 写完调用 `present` 交付，**不在正文里贴本地路径**。
- **不要**上传服务器或生成外链（除非用户明确要求外链）。

### 用户明确要求渠道推送时

用 `de_channel_send` 发送。附件走 `attachments` 参数（`path`/`url`/`base64`/`sessionImage`/`attachmentId`）。



| 类型 | 格式 | 禁止 |
|------|------|------|
| 图片 | `[🖼️ 查看图片](https://…)` | ❌ `![](url)` markdown 图片语法（部分渠道不渲染） |
| 视频 | `[📹 点击播放视频](https://…)` | ❌ `file://` 本地路径 |
| 文件 | `[方案文件：下载查看详情](https://…)` | ❌ 只给本地路径，让用户自己找 |
| 多素材 | 用 `·` 分隔 | ❌ 输出不可点击的纯文本 URL |
