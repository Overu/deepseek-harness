<a id="handoff-policy"></a>
## 移交规则

源码与已发布安装包的差异由[交付状态](operations.zh.md#current-delivery-state)维护；[收口记录](history/p6-closeout.md)保存结束阶段时的精确基准。后续问题按下表进入独立维护范围，不重新累计为未完成的迁移步骤。涉及新增官方 DSH 改动或 Stable 投放时，仍需原有规则要求的明确授权。

| 类别 | 查阅入口 | 处理方式 |
| --- | --- | --- |
| 后续版本 | 更新修复交付、打包流程优化 | 单独排期、使用新版本及对应验证，不覆盖已发布制品 |
| 已知 bug | V3 CDN、Windows 必要确认遮挡 | 保留复现背景和关闭证据，暂缓不代表修复 |
| 验证反馈 | 用户与平台反馈 | 收到实测反馈后记录结果，有问题按 bug 处理 |
| 产品决策 | 插件安装策略、暂缓产品取舍 | 维持已批准范围，明确取舍后再实现 |
| 检查债务 | 历史检查 | 触及相关范围时复现并修复，不新增全局豁免 |
| 明确排除 | 范围排除 | 不作为 P6 或后续版本必须补回的功能 |

| 类别与目标 | 背景和当前状态 | 后续处理与关闭条件 |
| --- | --- | --- |
| 后续版本：交付更新确认体验修复 | 当前源码已提交“安装并重启”单次精确版本授权、无任务免重复确认及 macOS 必要确认同窗；已发布 1.0.11 包不含这些改动 | 使用新版本构建并投 Candidate，验证实际包中的下载、取消、无任务重启及有任务确认。源码测试不替代制品验收；本次不打包发布 |

后续 rc 从 1.0.12-rc.1 或更高起。final 应用通过五连击手动检查 Candidate；本地签名序列覆盖后续 V3 选择与防回放，实际未来版本升级仍等真实交付验证。既有新 DSH 1.0.10/rc.1 的一次手动修复指引见[操作手册](operations.zh.md#current-delivery-state)。Stable 保持 1.0.9，晋升是独立发布决策。

<a id="plugin-installation-policy"></a>
## 插件安装策略

移交类别：产品决策。四个产品组件必须在执行端保护；当前管理器拒绝安装前无法确定真实包名的来源，本地归档预检上限为 10 MiB。这保护了必需组件，同时限制部分无关第三方插件来源。

后续需明确接受支持来源限制，或设计不修改当前 profile 的隔离包身份识别；目标是保留普通插件选择并阻止替换必需组件。当前未授权绕过或放宽检查，完整替代方案审阅前保留现有保护。[基线改动](baseline-changes.zh.md)维护理由；取舍及相应允许/拒绝回归明确后才关闭此项。

## 用户与平台反馈

用户报告 macOS arm64 从 1.0.8 升级到 1.0.10 成功，后续也反馈更新已恢复可用；没有新增完整的平台、版本路径或账号数据矩阵。P4 的旧数据副本验收属于另一组证据，不据此补记生产数据逐项通过。

| 类别与目标 | 背景和当前决定 | 后续处理与关闭条件 |
| --- | --- | --- |
| 验证反馈：平台、数据和失败恢复 | macOS x64、Windows x64 交第三方验证；账号、会话、工作区、插件、配置、再次更新、取消、网络恢复及在途任务仍有未观察的原生场景 | 按用户决定后续跟进，有问题转 bug；记录平台、当前/目标版本、账号环境、复现和受影响数据。不恢复 qualification 阶段，不要求另建环境来关闭清单 |
| 暂缓 bug：Windows 必要确认遮挡 | Windows 的共享遮罩为自绘标题栏保留 40px，直接挂到原生更新窗口会暴露底层内容。用户选择先不改共享组件，当前源码仅在仍需确认时保留原宿主，该提示仍可能被更新窗口遮挡 | 保持暂缓；以后获准适配原生标题栏留白时，补完整覆盖、输入隔离及取消回归，再做 Windows 实机验证。无任务免重复确认不等于此分支已修复 |

<a id="packaging-optimization"></a>
## 打包流程优化

移交类别：后续版本优化。[既有 CI 提速分析](history/shell/analysis/2026-11-02-dsh-insight-client-followups.md#提速建议与边界)保留为依据；随自然构建对照耗时，不为采集数据额外触发 CI。

- [ ] 交付独立的 App 票据重试维护：工作区实现已复用 DMG 验证器的有界只读重试，仅处理精确 CloudKit 错误。该任务报告恢复、无关错误和重试耗尽的本地回归通过，但 P6 收口时尚未提交，也未验证真实包。由该任务另行提交源码、测试、打包说明和基线理由，再验证后续制品；不记为已发布或已提交的 P6 基准。
- [ ] 交付并测量独立的 macOS 准备优化：工作区改动将 pack 与 runtime 准备改为和 Windows 一样并行。该任务报告本地检查通过，由其另行提交理由及改动，在下一次自然构建中对照耗时；目前没有实测提速或新包发布结论。
- [ ] App 已被 Apple 接受但 CI 未取得结果：1.0.11 x64 第二次在 notarytool 结果获取阶段失败，随后只读 Apple 历史及详细日志确认该 x86_64 提交为 Accepted。评估保留 submission ID 与脱敏失败 journal；仅在同一制品仍存在时查询原提交并恢复等待和附票，runner 清理后仍需重跑任务。不得跳过附票和最终验证。

[rc.2 记录](history/releases/1.0.11-rc.2.md#源码与原-run)与[1.0.11 记录](history/releases/1.0.11.md)保留失败、重试和恢复证据。有界验证重试仍失败或 runner 丢失制品时，按[运维恢复流程](operations.zh.md#known-failure-recovery)在原 run 重跑失败 job，复用其他平台成功产物。已接受提交的恢复仍未实施，需要另行授权并验证同一制品限制。

## 暂缓产品取舍

以下是独立产品或维护决定，不作为未完成的 P6 代码任务自动推进。

| 目标 | 上下文和当前结果 | 后续触发条件 |
| --- | --- | --- |
| 友好的插件名称与简介 | 本地入口可能显示绝对路径；package-meta 方案保留但未批准 | 出现明确显示问题时重议，获准后再改官方扩展 |
| 营销灵感库 | 用户选择保留旧测试接口和静态 fallback，后端归属/连接仍有争议 | 先确定后端归属与接入方式，再实施 |
| 更快恢复登录 | 隐藏窗口已消除登录页闪现，凭据校验和 Home 准备仍需时间 | 有可复现耗时或失败反馈时优化，不跳过校验或新建空 Home |
| 更小的 Main 接入 | 产品接线分布在多个生命周期位置 | 实际同步产生冲突后评估，不提前另建客户端或框架 |

<a id="excluded-scope"></a>
## 范围排除

随包独立 dsh CLI 适配、Windows 全局安装兼容、旧定时任务迁移、未归属会话修补、任意旧文件导出、Insight 界面翻译、已撤回的 sidebar 调整和内置技能内容验证均为排除决定，不是 P6 欠账，也不默认成为下一版本需求。Host、Agent shell、Memory 外部 CLI、技能脚本、历史读取和 Node 保留各自产品集成所需能力。
