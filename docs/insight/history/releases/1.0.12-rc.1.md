# 1.0.12-rc.1 打包优化测试准备

## 范围

Insight 打包输入和开发启动器的默认产品版本为 `1.0.12-rc.1`，内嵌 DSH 运行时版本保持独立。此次准备包含 App 票据验证的精确 CloudKit 瞬断重试，以及 macOS workspace 包归档与解释器运行时准备并行；三个平台 job 和完整制品验证流程保留。源码行为、失败条件和恢复方式见 [Desktop 打包指南](../../../../apps/desktop/packaging/README.zh.md#macos-release-signing)。

## 验证与测试准备

两项打包改动的六个测试文件共 133 项通过，覆盖 App/DMG 票据恢复、无关错误、重试耗尽、签名与 Gatekeeper 检查顺序，以及三个目标的准备步骤并行、等待和失败收尾。新增 Release 开关后，三个工作流检查文件共 14 项通过，确认关闭汇总时仍保留平台 artifact。Host/Client 聚合检查、定向 lint、文档链接和相关双语配对检查通过；独立审查未发现实质问题。全仓检查的既有失败由[后续事项](../../follow-ups.zh.md#historical-checks)维护，不把定向结果写成全仓通过。

后续性能对照固定源码、版本、平台和配置，分别记录构建、包归档与运行时准备、签名、App/ZIP 与 DMG 产物流、上传及 job 总耗时。并行阶段取实际经过时间，不累加两条任务耗时；记录缓存命中及重试次数。签名策略包含验证脚本摘要，此次脚本修改会使旧签名缓存失效，首轮样本需注明。实际耗时和 Apple 网络故障恢复仍待真实打包验证，不以单元测试耗时推断提速。

## 执行与发布限制

本轮仅提交源码和测试准备，未推送、未触发打包，也未创建 GitHub Release 或执行 OSS 发布；Stable、Candidate V2/V3 指针均未修改。后续性能测试使用 `version=1.0.12-rc.1`、`target=all`、`debug_skip_notarization=false`、`create_release=false`，保留正常签名、公证、三个平台的 artifact 收集及校验，跳过 Release 汇总。工作流默认仍创建 Release，测试必须显式关闭；配置说明由[运维参考](../../operations.zh.md#building-github-release-artifacts)维护。没有构建 run 或制品可供验收。
