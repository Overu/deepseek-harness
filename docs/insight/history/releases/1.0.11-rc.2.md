# 1.0.11-rc.2 Candidate 执行记录

## 范围

用户授权验证通过后提交更新检查修复，将 Insight 产品版本升级到 `1.0.11-rc.2`，构建 macOS arm64、macOS x64、Windows x64 并发布内测。仅发布 Candidate V3，不修改 Stable 或旧 final Candidate V2；不覆盖已发布的 rc.1 制品。

## 修复与兼容

Insight 专用 Electron fetch adapter 在禁止重定向且响应未重定向时补齐缺失的 URL，解决 1.0.10 和 rc.1 在版本比较前拒绝合法响应的问题。共用读取器的 URL、状态、签名、manifest、文件大小和哈希校验保持不变；没有修改既有官方 DSH 源码。根包和内嵌 DSH 运行时版本不变，产品版本通过既有构建输入传递。

已安装的 1.0.10 和 rc.1 无法通过 CDN 元数据自行修复，需要手动安装本次修复包一次；后续更新使用恢复后的检查链路。旧 Shell 仍只接受 V2 final 版本，rc.2 不向其旧指针投放。下载、安装及账号数据连续性的生产回归与发现元数据验证分开记录。

## 验证基线

前一轮源码验证包括适配与接线单测、真实 Electron 200/404 和 302 拒绝、真实 MacUpdater 发现 rc.1、构建产物及 Host/Client 聚合检查，以及独立安全审查。发现检查未下载或安装应用。一次并行原生测试超时及后续隔离诊断保留在 [rc.1 缺陷记录](1.0.11-rc.1.md)，不通过增加重试或超时掩盖。

全仓 doc-sync 的 2 项已知失败、固定业务源码及历史测试的 lint 问题保留；它们不是本轮新增错误，也不冒充已关闭。准确执行结果、源码提交、打包 run、发布 run 和公开渠道回读将在实际完成后记录。

### 发布后对账与 CDN 阻塞

arm64 和 Windows 首次发布成功。x64 首次发布在已上传 ZIP 的完整回读校验阶段出现 OSS `ResponseTimeoutError`（60 秒），尚未执行渠道指针切换。公开 OSS 原站验签确认 x64 仍为 rc.1，已上传 ZIP 的 HEAD 大小与 Release 的 421269817 字节一致；这不替代完整哈希校验。原发布 run 进入重跑，仍必须先校验现有对象的完整 SHA-512 再写指针，没有覆盖重试已有不可变对象。

公开 arm64 原生检查与独立 Node 检查均仍读到 rc.1。只读对比确认 OSS 原站已为 rc.2 且签名有效，而 CDN 的普通 URL 和带查询参数 URL 都命中旧缓存：`Age=11112`、`x-swift-cachetime=2592000`，即强制缓存 30 天；源站实际发送 `public,max-age=60,must-revalidate`。因此不是发布器写错版本，也不是本次 Electron URL 修复失效。三个 Candidate V3 指针需要修正 CDN 缓存规则并刷新，不能只凭 GitHub 发布成功宣称客户端已可见新版本。

查找私有阿里云控制台会话的操作被自动审批拒绝，原因是缺少访问该控制台的授权；已单独请求最小 CDN 配置授权，未通过其他方式读取私有控制台或修改缓存配置。公开 CDN/OSS 诊断继续执行。

### 已完成与剩余边界

三个 Candidate 发布 run 均已成功，x64 为原 run 的第二次尝试，使用的仍是原始发布器和同一份客户端字节。公开 OSS 原站的三个目标均通过当前 reader 的签名、manifest、updater metadata、版本和源码核对，均为 rc.2 / 上述源码。直接读取原站的 Stable 及三个旧 Candidate V2 指针，摘要与发布前相同；[指针摘要](1.0.11-rc.2-pointers.json)保留对照。

真实 Electron/MacUpdater 隔离诊断仅在临时进程内将读取来源改为公开 OSS 原站，返回 `isUpdateAvailable=true`、`1.0.11-rc.2`，未下载、安装或写入原账号数据。已安装客户端的固定 CDN 来源未改；公开 CDN 检查仍未通过，不能将原站诊断称为实际 CDN 更新验收。

进一步核对旧 Shell 发布实现后，确认其 OSS client 设有 30 分钟操作上限，而新发布器遗漏该设置，使用 SDK 默认 60 秒。本次仅在 Insight 自有 `oss.ts` 恢复 30 分钟设置并扩展既有 factory 断言；不增加自动重试，不改变 STS/OIDC、签名、哈希、不可变对象或指针规则。OSS/publish 18 项测试、定向 lint、Host/Client 聚合编译通过，独立审查未发现运行时阻断。该发布工具补正不进入客户端，不需要重建 rc.2；已成功的发布重试并未使用这一后补设置。

剩余项仅为已请求授权的 CDN 配置及固定 CDN 域名复测。已有 1.0.10 和 rc.1 安装仍需手动安装修复包一次，真实下载、安装和账号数据连续性继续按既有反馈流程跟进。
