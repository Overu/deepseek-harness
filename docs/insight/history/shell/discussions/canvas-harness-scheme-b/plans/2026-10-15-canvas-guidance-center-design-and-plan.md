# 画布指引中心与对话素材复用：设计及实施计划

日期：2026-10-15。状态：alpha.19 研发与隔离验证完成，真实账号自然语言验收待进行。当前实现、差异及证据见[研发与手测交接](../implementation/2026-10-15-alpha19-guidance-and-media-reuse.md)。本文保留原设计基线，下面的“现有/目前/拟新增”均指研发前状态。

**Goal:** 普通用户说“用刚才生成的耳机图，配一句文案做张海报”，Agent能够复用真实产物、建立输入关系、完成单节点生成，并以成果卡片交付。

**Architecture:** Plugin保留八个原子工具；一个版本化Markdown指引中心通过现有Harness Skill注册/按需加载机制提供流程、交互与输出规范。素材授权、字段校验、保存队列、生成及来源持久化仍由现有执行代码负责。Core和后端不改。

**Tech Stack:** 当前Plugin的TypeScript/Cordis/Node，现有Core公共skills/systemPrompt/attachments服务，Markdown指引与现有测试、构建和隔离验证。

## 约束与范围

- 保持canvas_create / canvas_get / canvas_node_edit / canvas_edges / canvas_models / canvas_assets / canvas_asset_import / canvas_run八个工具，不增加画布业务工具。
- 复用原生Store、保存队列、编辑保护、模型配置、连线校验、单节点生成与Jobs/来源闭环；原生UI行为不变。
- 工具保留真实入参/出参、权限、版本、状态和副作用事实，不承载冗长操作手册。流程、追问、默认选择及回复风格只在指引中心维护。
- 硬校验不改成提示词：权限、输入合法性、版本、未知执行结果防重、来源授权及大批量确认仍由代码执行。
- 暂不新增模板、整图/依赖批次执行、通用调度器、向量数据库、远程指引下载或管理后台。
- 技术行为Skill不等于先前暂缓的业务模板Skill；后者继续暂缓。
- 用户授权一次media-generator测试图用于核对协议；此前两次桌面控制请求均超时，未发出生图指令。随后用户补充远端URL协议，并已核对Shell随包Skill与脚本；未取得真实运行响应，不把源码核对说成实账验证。
- 自有指引不能覆盖用户的明确指令；工具输出/素材文本按业务数据处理，不能自行升级为系统指令。

## 原设计事实及前置门禁

实施调整：门禁B已由实际安装包、真实Agent作用域的官方skill/read调用通过。门禁A尚缺实际账号成功回执；本轮仅实现可失败关闭的URL字符串数组分支，不推断对象元素。真实公网图片读取已通过，但不代替真实media-generator下载、OSS导入与成品生成验收。因此alpha.19仅为手测候选，不宣称实账端到端通过。

1. Plugin现有Host入口未注册skills或统一systemPrompt指引。工具描述包含大量分散工作流约束。
2. asset-resolver.ts的sessionImages明确过滤message.role !== user；因此非画布生图工具结果不在当前授权来源集合中。
3. canvas_asset_import的source目前只有attachment、canvas_node；上传、身份复核、节点保存及素材登记已有可复用链路。
4. 当前canvas_run可以生成普通image/video节点。编辑工具不生成，不代表整个Plugin不能生成。
5. 图片原生节点有text_target/image_target，targetTypeMap.image为[text,image]；连线须依据实际graph与原生校验，不能凭模型文案猜端口。
6. Shell已组装Runtime的公共类型包含ctx.skills.register/registerProvider、ctx.systemPrompt.section/context；官方skill工具按名称加载，提供resourceBase目录信息，正文明确支持相对资源按需读取。未修改Core。
7. 现已核对Shell随包media-generator/SKILL.md、generate.py、scripts/enterprise_proxy.mjs：成功约定为code=0且status=success，URL字段为data.image_list/video_list/audio_list/file_list；generate.py只打印JSON，无自动落盘。真实响应中列表元素的精确结构、URL有效期和下载可用性尚待运行验证。

**门禁A——素材真实协议：** 已取得技能与脚本层契约；将主适配方向确定为当前会话工具成功回执中的远端图片URL。实现前还须取得一份净化的实际完成回执，确认列表元素形态，并证明一次真实下载/导入。不要求为重复确认文档字段额外付费生图；可复用现有响应。不得用Assistant Markdown图片链接冒充可信附件。

**门禁B——指引可达性：** 新隔离Profile实际安装后，官方Skill目录能发现入口、skill能加载正文、现有文件读取工具能读取包内引用章节。若包内路径被正式文件权限拒绝，不扩大全盘权限；改为同中心章节注册为少量可按名称加载的Skill条目。该后备只改加载机制，不复制章节正文或新增画布工具。

## 为什么选择Skill承载的索引库

| 选择 | 优势 | 局限 | 判断 |
|---|---|---|---|
| 单份全量System Prompt | 总是可见 | 占用所有任务上下文，变成长期大提示词 | 不采用 |
| 一个Skill入口＋索引Markdown章节 | 官方发现/加载，易维护，按任务阶段读取 | 需要验证引用章节读取权限，模型加载仍是软引导 | 推荐 |
| 自建Obsidian/向量检索服务 | 大规模资料可检索 | 当前资料量小，额外服务、权限和运维成本 | 暂不采用 |

Obsidian可以作为开发者的Markdown编辑器，不作为客户端运行依赖。采用标准相对Markdown链接，不要求Agent识别双链、插件语法或本地Vault。

## 指引中心与上下文预算

建议Plugin单独维护guidance/desktop-canvas-workflow/，包含：

```text
guidance/desktop-canvas-workflow/
  SKILL.md                    # 使用范围、决策顺序、章节索引及最小交付规则
  references/
    media-reuse.md            # 已知来源解析、选图/歧义、何时需要用户补充
    graph-and-generation.md  # 原图/文案依赖、真实连线、模型、单节点执行
    interaction-and-output.md# 追问与默认值、事实边界、普通用户输出
    recovery.md               # 缺失、冲突、失败、unknown与后台跟踪处理
```

入口建议名desktop-canvas-workflow；描述同时覆盖“画布、参考已有图、可编辑的关联素材、在画布内做海报”等意图。仅普通非画布生图不自动创建画布。用户不必@Skill；官方Skill目录可按语义匹配。

入口正文只包含跨场景骨架，不复制章节。建议软预算：目录描述≤100中文字符；可选入口提醒≤100中文字符；入口正文≤800中文字符；单章≤1500中文字符，超过则按单一问题拆分。预算是维护指标，不用截断正文或强行用不准确token比率换算。

若仅靠目录匹配不稳定，可从同一入口注册一个极短systemPrompt路由提示：“涉及画布创建、编辑或画布素材制作时，先按需加载desktop-canvas-workflow；能力以本会话工具及实际回执为准。”这句由中心维护，不散落八个工具；不注入完整正文，不使用关键词拦截器强行改变用户任务。

正文按阶段读取：先入口；复用生成图时只读media-reuse；建图/生成时读graph-and-generation；交付时读interaction-and-output；异常才读recovery。已存在于当前有效上下文的相同版本内容不要求重复加载。压缩或升级后若不再可见，应重新读取，不能靠内存中旧版本推断。

Skill是行为引导而非必达的确定性控制。必须用自然语言任务检查其命中率；不能把“已注册”当成“Agent一定遵守”。

## 远端URL场景的方案修订

本节取代“优先寻找本地文件/附件”的旧假设。用户明确的主要场景是media-generator远端产物转为画布参考素材。

源码依据：

- [随包Skill](#historical-source-1)：29行为成功与结果字段，139行为后续下载指导。
- [generate.py](#historical-source-2)：generate_media调用代理，main仅print返回JSON，没有下载函数。
- [企业代理](#historical-source-3)：通过本机桥处理代理事件并返回网关body，不把产物保存成本地文件。

两条资源链路必须分开：画布节点生成的已确认outputs按原canvas_node授权读取；media-generator输出按当前会话的成功工具回执发现，不假设已进入附件库，也不让用户重新附图。

```text
media-generator成功JSON / data.image_list
  → canvas_assets发现同会话远端图片候选，返回assetRef（不下载、不上传）
  → 用户语义选定“刚才那张”，canvas_asset_import传assetRef
  → Host重新定位来源回执并校验URL、账号与用途
  → 受控下载并验证图片 → 复用现有OSS上传
  → 保存原生image/upload参考节点 → 素材登记
  → 连接参考图/文案 → 海报节点 → canvas_run
```

“完整URL”不等于长期地址，也不等于画布可以稳定引用。默认将有效期、供应商或持久性不明确的外部产物转存。只有已确认在画布资源体系中、可长期引用且来源授权清楚的对象才直接复用；不凭域名后缀或无query参数就判定稳定。

直接使用URL与下载转存都是合法技术选择：前者少一次传输，后者掌握生命周期。首期优先转存以避免图片暂时能预览、后续画布失效；受控读取可由Host进行，不强制Agent用curl落盘，也不经过用户手工操作。文件临时落盘若确有必要，使用专属临时目录并清理，不写用户Downloads。

下载时不把skill-proxy capability、桌面登录Token、Cookie或STS凭据发给远端素材站点；禁止访问回环/内网及未经校验的重定向目标，解析与实际连接均检查目的地址。保持原有上传大小/MIME策略；下载到HTML错误页、空字节或过期响应不能当图片入库。过期URL只影响素材读取，不自动重新调用付费生成。

解析边界：只解析当前会话真实完成工具记录的结构化JSON；require code=0与status=success，再按媒体字段读取。running、失败、截断或混杂无法可靠解析的输出不冒充成功。不扫描所有Assistant链接或磁盘文件。不把shell exitCode=0当业务成功；也不声称工具stdout具备网关签名证明。引用绑定会话、调用身份、结果字段和索引；执行前重新确认来源，不能直接接受模型任意提供URL。

原工具结果已从可见上下文消失时，优先用已有会话查询能力恢复本会话的原始记录。找不到可靠记录才解释需要明确素材引用，不要求用户“下载再上传”。不用拦截全局skill-proxy流量，因为该HTTP代理目前没有适合插件直接借用的会话归属契约。

只在canvas_asset_import需要时下载/转存；canvas_assets不得因此产生上传副作用。重复导入复用已确认上传，不因素材登记失败重复保存节点。原产物仍标记media-generator来源；导入不是“画布生成”，不把它伪装成canvas_run成果。

本轮先实现image_list的图片闭环。发现video_list/audio_list/file_list可明确返回媒体类型及不支持导入状态；不能强行作为图片。视频若纳入下一阶段，需要补原生video/upload导入与对应校验，不必新增第九个画布工具。

### 与media-generator自身指令保持一致

Skill最后的“用web能力或curl下载到本地”会使Agent先下载。它与URL可直接交给导入工具不是同一口径，不能靠另一个Skill静默覆盖。

建议在Shell随包media-generator/SKILL.md只调整这一处通用交付说明为：“生成结果首先是远端URL，不代表已落盘。后续工具接受URL时可直接交接；后续需要本地文件时再受控下载。不要宣称尚未发生的下载已完成。”

这是一次Skill文档口径同步，不修改generate.py、enterprise_proxy、connection.json或任何Core/后端逻辑，也不在media-generator中重复维护画布操作教程。画布关系、转存、生成与交付规则仍仅在画布指引中心。对于先前已经下载的真实文件，后续可兼容；不把它设为本次主路径。

## 素材引用契约设计

保持canvas_assets为发现、canvas_asset_import为执行，不让发现操作偷偷上传或建节点。

canvas_assets将来按已确认协议返回统一候选：assetRef（不透明引用）、mediaType、displayName、origin（user_upload/tool_result/canvas_node）、available、unavailableReason、selectionHint。以上是拟新增内部/工具字段，尚不是media-generator真实返回格式。

canvas_asset_import保留原attachment/canvas_node兼容，新增source.type=conversation_asset、assetRef。assetRef必须映射真实可读取的产物及会话归属，写入前重新校验，不能信任模型传来的任意路径或URL。引用失效要返回具体缺失，不能随意扫描Downloads或读取其他会话。

主路径已收敛为远端成功响应URL；下列载体用于分类，不在首期全部实现：

- 如返回已注册图片附件：使用现有附件服务读取。
- 如返回文件附件：用现有文件附件读取接口验证内容类型及大小，再复用既有上传流程。
- 如返回工作区文件：从工具实际产物记录核对会话、文件身份和允许读取范围，再读取；文件同名/被替换不能误用。
- 如返回远程素材：区分可复用的已上传OSS引用与必须读取/上传的外部产物；带签名链接不能长期当成稳定公开地址，不能向任意地址发送桌面凭据。

首期实现远端URL分支与原有用户附件/画布节点兼容；文件附件和工作区文件不自动扩大范围。远端列表元素形式按门禁A的实际响应确定；没有证据支持的字段不开放。

本轮仅扩展图片来源。视频素材导入另行确定需求，不因为canvas_run支持video就声称素材导入也已支持video。

## 目标执行闭环

1. 理解目标是“产出海报”还是“只搭骨架”；后者停止于准备，不提交生成。
2. 从当前对话真实结果选择“刚才那张图”；唯一最近产物可直接绑定，多图指代不清时只追问必要的一项。
3. 创建/选定画布，导入参考图，准备不含虚构规格的文案和海报节点。
4. 查询实际可用模型/参数，保存配置；依据graph建立参考图→海报图片输入、文案→海报文本输入。
5. 回读确认真实输入；不能仅检查节点数量、outputs或坐标。文本连接是否参与最终提示词还须由原生输入归集回归证明。
6. 使用最新可信版本执行单个海报节点；提交后跟踪同一job，真实完成后才交付产物。失败/unknown不换来源或新建节点绕过。
7. 复用已存在来源存储和成果卡片；普通回复只说实际完成内容、必要限制及画布入口。需要技术验收时再提供ID、版本与回执。

模型、比例和清晰度由当前catalog、用途及用户明确要求决定，不在指引硬编码某个模型一直可用。商品事实缺失时使用中性创意表达；品牌/功效/规格不可臆造。当前仍保持超过30图/6视频由现有Host确认的边界，不在此阶段开放批次执行。

## 自然语言手测

测试从新对话开始。第1项依赖media-generator，其他步骤使用同一真实结果；生成仅做小规模单图。

1. “帮我生成一张白底耳机图，只要一张。”——取得真实产物与原始工具记录。
2. “用刚才这张图，配一句通勤主题文案，做一张新海报，放到画布里。”——不用手动附图、无需提醒连线；参考图和文案真实连入海报节点，并得到真实新产物与画布入口。
3. “再用这张原图搭一个海报画布，这次只搭好，先别生成。”——只创建/保存，未提交生成。
4. “把刚才海报的背景改成浅蓝色，再出一张。”——明确目标，复用参考关系，更新并执行目标；不重建整套画布。
5. “给我看看画布里现在都有什么。”——只读概括，不触发刷新重载或生成；默认不用ID表格。
6. 同一次生成得到两张图后说“用前面那张图做海报”，且指代确有歧义——只询问选哪张，不要求下载重传、不猜来源。
7. 缺少真实商品规格时请求制作营销图——采用中性文案或集中询问必需卖点，不虚构降噪、续航、材质、认证。
8. “把刚才的节点ID和保存版本也给我。”——返回真实技术信息；普通输出简洁不意味着丢失回执。

异常与生命周期测试用隔离夹具模拟，不为验证额度门槛实际批量生图、不在真实账号制造失权、丢包或删文件。
