## 4 启动、账号与数据流

```text
Insight Main 启动
  → 隐藏登录窗口恢复加密凭据
      → 无凭据/失效/离线等：显示现有 Insight 登录页
      → 账号身份及 Home 就绪：进入 DSH 原生工作区
  → 使用原 Shell userData + 环境/稳定 user ID 对应 scope
  → insight/accounts/<scope>/harness 作为 DSH_HOME
  → DSH Host 加载四个必需组件、既有工作区和 Session
  → Integration 提供受控账号/模型/业务认证，Canvas 等消费能力
```

手机号和显示名不决定数据目录。P4 不导入、转换或合并历史，`harness-native` 保留不自动合并；仅有该预发布目录时提示人工处理。旧 web profile 和第三方配置文件保留，不承诺每条配置都自动成为 desktop profile 的有效配置。首次允许重新登录，登录不应清空旧 Home。

账号生命周期由 Main 负责，renderer 不获得原始凭据；退出或切换时停止旧账号请求和 Host，避免迟到请求跨账号。模型 token 在 Insight 维护，用户不配置模型凭据。保留 Agent shell、专家技能脚本、Memory 外部 CLI 所需运行时路径；这与独立 `dsh` CLI 产品支持无关。

新旧客户端不得同时写同一 Home。保留数据不代表支持旧二进制读取新数据或无损降级；不要新增格式转换、会话补归属、旧定时任务暂停/恢复或独立迁移状态机。P4 的旧数据副本首启和重启证据保留，线上升级后各项数据核对仍待反馈。

## 5 构建与发布流

构建采用 DSH，发布沿用 Shell 的 OSS/CDN 链路。`insight-package.yml` 生成三平台 Release 制品，`insight-publish.yml` 用轻量依赖读取已有制品，不重建。macOS 已签名并公证；Windows 按用户决定不签名，保留 DSH/NSIS 并用 Insight 品牌，当前用户安装范围内兼容旧注册目录；新装末级目录为 `insight-desktop`。不恢复 Windows qualification 或全局安装兼容。

网关通过 GitHub OIDC 交换 OSS STS，audience 为代码规定的 `insight-harness-oss-upload`，请求体 `{}`；未配置长期 OSS AccessKey。新的仓库身份已获网关放行并实测发布成功。签名材料仅由 GitHub Secrets/Environment 提供，文档和客户端均不得保存私钥。

final Candidate V2 与 Stable 可复用相同不可变制品和目标清单；rc 使用 Candidate V3。当前源码双协议 reader 已完成，但已发 1.0.10 未包含，下一次自然客户端发版需带上；当前 1.0.10 通过 Candidate 接收修复需走 rc 通路或手动安装。普通 final 客户端只检查 Stable，五连击确认后手动检查 Candidate；rc 客户端常规检查在没有可升级 Stable 时也检查 Candidate。

新仓是唯一发布入口。旧 Shell 原仓和 fork 的两条 publish workflow 已停用，构建/签名 workflow 未停；旧 STS 权限尚未撤销。指针采用单发布者串行、写前核对和写后回读，并非原子 CAS。不得并行启用旧发布器；Stable 发布、权限撤销及新增后端调整需要各自明确范围。

## 7 P6 执行顺序与完成标准

1. 在当前 insight 仓库只读盘点候选遗留：运行消费者、profile、构建引用、资源、父仓补丁、文档和测试。先提交删除清单及替代去向；不要从“旧”或“复杂”推断无用。
2. 分类为已替代且无消费者、仍需历史读取、仍是业务需求、待确认争议。仅清理第一类的实现及专属配置、文档和测试；仍有效的回归用例转到现有所有者，历史读取不可被执行器退役连带删除。
3. 核对官方修改台账、源码快照更新和上游同步说明。上游已完整覆盖且无剩余消费者时再移除本地接入及专属测试；新增官方范围仍单独确认。
4. 将 Shell 的迁移报告搬入当前 DSH 仓库的 Insight 文档区，建立面向人类和 Agent 的总览及按问题查阅路径；梳理重复说明，保留有价值的历史证据并修复引用。包内 README 保留就近入口，现行事实只保留一处维护所有者。
5. 按实际清理面运行定向检查和构建检查，交付变化、删除依据、保留理由、检查结果及后续 bug 清单。不要因文档清理重新打包或发布，也不恢复冗余资格阶段。

P6 完成要求：范围内功能都有明确实现去向，清理项没有仍在使用的消费者，必需组件和技能同步方式保留，只有一套活动启动/打包/更新链，官方差异和维护文档可追踪，未验证项和已知问题有明确转交。P6 完成不自动授权 Stable 发布，也不把第三方尚未反馈的结果记为通过。
