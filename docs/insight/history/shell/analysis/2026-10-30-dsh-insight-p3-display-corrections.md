# P3 插件名称与技能弹层补正

日期：2026-10-30。范围：首轮验收后用户提出的插件绝对路径标题、简介缺失及技能布局差异。仍在 P3，不进入 P4。用户已明确暂缓插件名称的官方扩展，并批准 Main 与打包配置中的内置资源接线；后者已实施，解锁后的原生列表、搜索和多选复测通过。

## 插件名称与正式打包

四个私有 bundle 的配置声明是相对入口 `./lib/index.js`。DSH composition 按该 bundle 的所在位置解析出 `file://…/lib/index.js`，Loader 以它加载代码，完整插件库存又把它作为 moduleName。现有元数据读取只接受包名，忽略文件地址，设置页便将完整地址作为标题后备值，且没有简介。

这不是把开发机目录写死在配置中：安装后会按安装位置重新解析入口，不能仅凭界面中的绝对路径判断正式包受限。正式安装位置、ASAR unpack 和真实 Loader 仍需制品 smoke 验证，不能把展示修复等同于打包验证通过。

不应为修正名称把加载入口改为自身包名：bundle 相对入口承担现有包解析要求。也不在 Insight 中维护另一份“绝对路径→文案”表。

建议在现有官方元数据读取中增加一个无缓存的受限入口：

```text
Loader 的 file URL
    → 定位候选包 manifest
    → 以该文件 URL 为 parent，按 Node 自引用解析该包的根导出
    → 双方经现有 realModuleFile 规范化后完全相等
        → 复用现有包元数据读取
        → 设置页显示包声明的标题/包名和简介
      不相等
        → 不关联根包元数据
```

“同目录”或“最近的 package.json”不足以认定归属，必须等于根导出的实际目标。四个私有包现有 `exports["."].default` 与相对入口一致；其他文件、Client 子入口、普通本地脚本不获得根包标题。包名只用于读取元数据，实际 Loader 入口不变，也不新增 composition 映射或 HMR 缓存。

| 区域 | 计划变化 | 授权状态 |
| --- | --- | --- |
| 官方 packages/boot/app-boot/src/package-meta.ts | 仅接受精确根导出的文件地址，再复用 manifest/locale/icon 读取 | 用户明确暂缓，未修改 |
| 官方 app-boot 的元数据测试、README/JSDoc 和基线修改记录 | 覆盖根入口、非根文件、符号链接、Node 导出条件、原包名行为与打包 smoke | 随方案暂缓，未修改 |
| Insight 各包元数据 | 使用包自身名称与简介；Canvas 补缺少的 description，不另外开启产品 i18n 工作 | 随显示修复暂缓 |

## 技能弹层

原 Shell 的用户可见分组是“平台预置 / 用户自定义”，不是三个并列来源。平台预置来自根 bundled-skills；用户自定义合并账号和共享安装位置。底层仍保留来源标识和 DSH 的技能优先级，合并展示不改变同名覆盖规则。

本轮私有 Integration 已恢复紧凑“专家技能”触发器、搜索框、两个来源标签、名称/简介/选中标记，以及 360px 卡片中的独立列表滚动。简介可完整换行，避免只能依靠鼠标 title 阅读截断内容。UI 使用 DSH 原有 Menu、图标与颜色变量，不照搬旧 Shell 的布局测量、全局样式注入和 Remote 兼容回退。

Host 从每个已发现技能旁的可选 ui.json 读取 displayName 和 shortDescription；它们仅影响显示与搜索，选择仍调用原始技能名称。读取只接受有界普通文件，拒绝符号链接与特殊文件，取消会向上透传；缺失或损坏的 UI 标签回退到技能原生名称/描述，不隐藏该技能。目录暂时不完整或技能解析暂时失败时，保留已观察到的标签。

这些变化不改 bundled-skills 内的文件，不验证其中的说明、脚本或业务正确性。内置来源不会改成从 Memory、自定义技能或硬编码清单凑数。

## 已授权的内置资源接线

用户已批准这两处最小接入。Main 仅对 Insight 固定 DSH_BUNDLED_SKILL_DIR，开发时使用仓库根目录，安装后使用 resources/bundled-skills；清除继承的大小写变体，启动前打开、枚举并关闭目录，失败时不创建 Host。官方产品保留原有目录环境。electron-builder 通过 Insight 专用 extraResources 整目录复制，并同步现有配置声明的资源类型。目录名称、层级和外部仓库同步方式不变。

已验证实际 builder 资源复制：322 个文件或链接的相对路径、摘要与可执行位一致，源目录未变化。该检查只验证资源交付，不评估技能正文、脚本或业务结果。Main/打包的两个测试文件共 161 项通过，包括普通文件拒绝、缺资源拒绝、账号失效竞态、官方行为及两套目标配置的复制。详见 [验收记录的接线结果](2026-10-30-dsh-insight-p3-acceptance.md#已授权的内置资源接线结果)。
