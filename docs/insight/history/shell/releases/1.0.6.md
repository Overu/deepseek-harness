## 已修复问题与边界

- 旧 V3 会话的确切工具调度故障留下未结算调用，新 V4 校验拒绝迁移，消息源文件仍在。Core 仅修复具有同回合、紧邻结束事件及确切旧错误证据的记录；补入错误结果、不执行工具、不虚构成功、不放宽原生 V4 校验。五份历史副本及旧 1.0.4 V4 读取器验证见[兼容修复记录](../analysis/2026-10-09-session-history-compatibility-repair.md)。会话观察恢复后，相关模型投影与专家技能恢复。
- 本地 `.tgz` 插件导入先保留原归档到当前 Profile 管理目录，再调用官方插件安装路径；不恢复此前已经丢失的归档，也不恢复用户主动卸载的插件。错误归因仅在安装源或依赖证据能够关联具体第三方插件时成立，见[插件启动故障分析](../analysis/2026-10-09-local-plugin-upgrade-startup-failure.md)。
- 桌面画布 `0.3.0-alpha.7` 的普通依赖曾遮蔽新 Core 服务，触发官方兼容预检和必需插件启动失败。需另行升级到使用兼容宿主 peer dependency 的 `0.3.0-alpha.8`；升级客户端不会替用户升级第三方插件。
- Shell 增加历史失败状态、技能不可用原因和只读历史导出；导出限制为 32 MiB，拒绝覆盖历史代际及已有文件。未匹配的异常旧日志仍可能拒绝迁移。

## 验收范围

三平台 CI 证明实际安装包内 Runtime 可启动、脱敏旧 V3 可迁移、可在恢复阶段续写并重新打开。该矩阵中 Candidate 和 recovery 都是修复后的 `c3aaab2` Core，不等于旧 1.0.4 整套应用的人工 GUI 回退。另有五份真实历史副本通过旧 1.0.4 V4 读取器的验证；用户在 macOS ARM64 确认卸载重装后正常启动、历史和专家技能恢复，并完成 Candidate 验收。

macOS 两个目标的强制 CI 门禁包含 Developer ID 签名、公证、应用及 DMG staple 和容器校验。Windows 未新增 Authenticode 签名。旧协议签名链及 HEAD/Range 证明发现与下载能力，不代表 Intel/Windows 人工 GUI 升级、所有插件组合、Memory Evolve、真实收费业务链或全量旧日志已经验收。
