## Scope

This record identifies existing DSH files changed for the private Insight source intake and Desktop integration. It excludes unchanged upstream source and implementation files owned by new private packages. The official Desktop remains the default product and retains its startup, profile, account, window, and update behavior; the Insight path is selected explicitly before Electron reads product state.

## New integration owners

The update-coordinator extension, single-updater Main adapter, update-window compiler entry, and product packaging extension are the four explicitly authorized official hooks for P5. The `tsconfig` alias belongs to the compiler entry. The three Windows branding files and the DMG validation recovery in the table are four additional authorized official files; no locale-helper, C++ caller, or notary-executor change belongs to this scope.

The exact private package roster lives in [insight-package-policy.ts](../../scripts/insight-package-policy.ts). [Insight product integration](architecture.md) describes runtime ownership, source snapshots, and synchronized skills. The [Desktop Integration package](../../packages/insight/desktop-integration/README.md) owns authentication and account process behavior. Each fixed business package's `upstream.json` and the replayable differences under `patches/insight` identify imported code and local adaptation.

The Desktop Integration package also owns signed update discovery, local rollout state, candidate confirmation, and renderer-safe update actions. Desktop Main owns the only electron-updater instance and the native window adapters. [The Insight release scripts](../../scripts/insight-release/README.md) own artifact manifests, GitHub workflow and attachment identity verification, signing, the single publisher's pre-write reconciliation and post-write readback, and the separate stable and candidate publication formats.

`bundled-skills` keeps its source repository's internal structure. The imported label generator preserves the previous directory-to-client metadata flow. Its test uses synthetic files; it does not assess built-in skill content or business results.

[The Canvas source acknowledgement](../persistence-changes/2026-10-28-insight-canvas-attribution.md) records reader compatibility without changing the Session writer or migrating user data.

## Host value dependency classification

`createUserMessage`, `BlockAssembler`, and `domainTable` are exact safe Host exports. They return structural values or retain caller-owned state; they do not require consumers to share a service constructor or module-level state. Canvas and Prompt declare their corresponding runtime dependency edges. `defineTool` remains a shared peer because its argument failures must retain the Host pipeline’s error-class identity. Other exports from these provider packages retain their existing classifications. A pull request carrying these additions must disclose them under a prominent Host dependency classification heading as required by `scripts/package-dependency-policy.ts`.

The managed Gateway imports `LlmAdapter`, `LlmError`, and `resolveImageAttachmentAccess` from `dsh-llm`, `resolveAdapterOptions` from `dsh-llm-deepseek`, and `PiAiAdapter`, `resolveProfiles`, `credentialStoreFrom`, and `authContextFrom` from `dsh-llm-pi-ai`. These eight exact exports are peer-required: the private bundle uses the Host's adapter, error, profile, and auth implementations rather than installing another provider copy. They add no duplicate-safe exceptions.

## Necessity and implementation choices

The product requirements are confirmed; the implementation is still a maintenance choice. The table separates required behavior from the exact shared extension. The fixed comparison and per-file commit evidence are preserved in the [preflight review](history/shell/analysis/2026-11-02-dsh-insight-p6-preflight-review.md); the live Git diff remains authoritative for current file changes.

| Requirement | Why the existing extension points were insufficient | Decision and trade-off |
| --- | --- | --- |
| Login before the business Host and reuse the old account Home | Host plugins cannot gate the pre-Host Electron lifecycle or own native encrypted credentials | Keep the Main/Host integration; no parallel launcher or client. Main wiring is a maintenance cost to reassess after a real baseline merge, not a reason for a speculative framework |
| Managed model authentication | The introduced Pi AI package did not export the existing profile/authentication helpers needed by the gateway | Export the three helpers instead of copying their implementation; remove the local difference when upstream supplies equivalent exports |
| Four required components | Default installation and disabled UI controls cannot prevent Host/tool/API removal or replacement; old profile configuration can override normal bundle config | Keep execution-layer protection and Main-owned policy. Its current rejection of unidentifiable install sources, including over-limit local archives, is a product limitation requiring a separate decision |
| Shell-equivalent skill selection | Whole-draft replacement can discard atomic references, quotes, or excerpts; existing public actions did not safely toggle arbitrary skill tokens | Keep the approved toggleSkill/selectedSkills extension. It adds a skill concept to a shared input API; revalidate editor projection when upstream changes it |
| Canvas historical node references | The source-decoration chain can add presentation but cannot replace tagged body text while preserving the full native message row | Keep the complete-row Factory rather than a Canvas copy of the native row. Source-chain ownership is a shared semantic change and needs regression coverage |
| Signed OSS discovery with one updater | The built-in source selection did not bind Insight's verified metadata and channel choice to the existing updater candidate | Keep custom-provider and target binding in the serialized coordinator; retain separate download/install approval and lifecycle ownership |
| Brand, packaged skills, and old installation continuity | Product identity, native resources, runtime closure, and NSIS path checks are owned by Desktop packaging | Keep scoped product inputs and current-user compatibility; do not restore all-users support or the removed qualification stage |
| macOS build reliability | Observed staple and post-notarization ticket-validation failures occur at different stages | Keep the validated dependency upgrade and bounded read-only validation retry. Neither is Insight business functionality; both affect official builds too |

## Baseline-update impact

A product switch limits runtime behavior but does not remove source, dependency, or semantic coupling. Main, Host startup/shutdown, the update coordinator, the message Factory, and editor projection need manual alignment when upstream changes their behavior. Plugin installation and the packaging/runtime layout are the next affected areas. The three helper exports and exact package classifications are smaller additive differences. A clean Git merge is not acceptance evidence.

The notarization dependency change from 2.5.0 to 3.1.2 crosses a SemVer major version. Treat it as a shared build-dependency upgrade, not a patch-only maintenance update. It handles staple retries; the local CloudKit rule handles a later read-only DMG validation. Remove either local difference only when the replacement preserves that stage's behavior.

Use a known-good checkpoint before a baseline merge. Read the upstream changes for the affected owners, merge without overwriting shared history, reconcile the lockfile with the package manager, and regenerate catalogs from source instead of hand-resolving generated output. Run focused behavior/recorded-session checks for affected consumers; use a real package when runtime layout or installer behavior changes. A documentation-only merge does not require a new package build. This P6 review did not execute a newer baseline merge, so the relative costs above are not measured time estimates.

The [follow-up list](follow-ups.md) carries plugin-source policy, platform feedback, and historical check debt. Keep evidence for necessary behavior; remove local integration and its exclusive tests only after an upstream replacement and its actual consumers have been verified.
