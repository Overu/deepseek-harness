# Insight 桌面构建输入

[English](insight.md) | 中文

## 摘要

Insight 组件保留已有包名和加载标识，同时使用工作区中的 DSH 实现。其 manifest 是私有的，运行资源归入桌面依赖闭包。官方 Desktop 的启动、登录和更新流程保持不变。

## 源码归属

[packages/insight](../../packages/insight/README.zh.md) 拥有三个源码包。各包在 `upstream.json` 记录上游仓库、提交和版本；工作区版本跟随 DSH 根版本。源码改动提交到父仓，`patches/insight` 中的差异支持相对固定输入回放。正常构建不会给已安装文件打补丁。

[产品清单](../../scripts/insight-package-policy.ts) 中的精确标识接受私有状态、版本、发布元数据和唯一工作区拥有者检查。npm 基线只排除这些精确目录，其他包、依赖和 Client 模块检查仍然有效。

Canvas 和 Memory Client 保留上游 `strict` 编译模式。这些编译配置未启用 DSH 额外的精确可选属性与索引访问检查；源码接入不改变既有索引和可选值行为。

`verify:insight-source` 将本地固定归档和父仓补丁与包的完整权威源码核对。命令先验证归档摘要，再在自有临时目录提取，拒绝缺失、多余或变化的文件，不获取输入，也不编辑工作区。

## 技能资产

`bundled-skills` 保持为外部同步的根目录，内部结构不变。客户端标签生成器读取既有名称和 `ui.json`，桌面打包保持该目录与插件包分离。技能内容、脚本和业务正确性由来源仓库负责，不属于本次迁移。

固定 Memory 源码不再获取或检出独立 Git 更新，组件更新归 Insight 客户端发布流程负责。引入界面的文案仍需在产品验收前完成独立的本地化迁移。

## 桌面集成

三个包进入桌面构建依赖闭包，但不由官方 profile 挂载。Insight 原生认证、账号 Home 选择和更新来源接入与本次源码引入分开。Canvas 云操作仍需要账号通道和受支持的浏览器传输。
